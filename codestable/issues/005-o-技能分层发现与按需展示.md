# 技能分层发现与按需展示：来源表、插件、地图和检索

## 做成以后是什么样

AI 在任意入口连上 winhand 时，看到的技能不再是平铺的上百个。分三处给：

- **开场看到一张很短的技能地图**，它几乎不变。内容是：
  - 主人钉住的几个常驻技能；
  - 8 行中英双语的领域，每行带个数和例子；
  - 带专属技能的项目，每个项目带个数；
  - 一句行动契约：要用专门工具处理文件、设备或项目流程时，先用任务原话查一次 `skill(query=…)`。
- **`context(path)` 列出这个项目自己的技能**，每个都带描述。
- **其余技能靠 `skill(query=…)` 检索**，范围是全机：全局目录、已启用的 Claude 和 Codex 插件、各个项目里的技能。检索结果给出每个技能的 id 和来源，然后用 `skill(id, path=…)` 取正文。

发现层也补齐了，md2visio 的 `.codex/skills`、Trellis 的 `.pi/skills`、插件技能都能找到。

**范围：**

- 包含：
  - 技能来源表：项目链、用户目录、Claude 与 Codex 的已启用插件；
  - 稳定 id，同一个文件只出一条；
  - 项目信任标注；
  - 能力地图，有三个出口：MCP 说明、云端开场 hook、`context()`；
  - `skill` 加上检索；
  - `winhand skills` 离线报告；
  - 三个现成 bug：
    - `skill(repo, path)` 丢掉子路径；
    - `skill(path=子目录)` 把起点当成了项目根；
    - `brief` 模式丢掉 id。
- 不包含：
  - `--add-dir`；
  - 受管、系统和 claude.ai 同步来的技能；
  - Pi 包；
  - 按调用方过滤；
  - 自建包管理器。

## 为什么现在做

主人说技能获取是 winhand 的硬伤，朋友的 pi-bridge 全局、局部都能检测到。2026-11-22 到 23 日，在 parley 的 t18、t21、t22 三个线程里，和 astra（gpt-6.2-astra）、agy-neon（gemini-4-neon-high）讨论过三轮，用 smart-search 查过公开资料，又在本机实测。结论：

- **保留 winhand**。pi-bridge 的技能机制和 winhand 一样，都是先列名字和描述，再读 SKILL.md；它只是多一个 Pi 包来源。另外它还缺作业跨重启和任务结束叫醒。
- **漏检是扫描范围太窄**：
  - 项目层只看 git 根下的 `.agents/skills` 和 `.claude/skills` 两处，而且只看一级；
  - 不读插件的启用清单。

  本机 winhand 列出 81 个技能，另有 31 个已启用的 Claude 插件技能和 55 个 Codex 插件技能没看到。md2visio 的 `openspec-flow`、Trellis 的 9 个 `.pi` 技能也没看到。
- **平铺上百个技能太乱**，主人不想要。公开资料（`C:\Users\dxt98\.winhand\scratch\skills-research\digest.md`）里，各家的做法是：
  - 渐进式披露：先给名字和描述，用到时才读正文；
  - 第一层有预算：Claude 是上下文的 1%，Codex 是 2%；
  - 可见性开关：Claude 的 `skillOverrides`、Codex 的 `[[skills.config]]`。

  各家都不做强制隔离。

决定笔记：`.agents/notes/implemented/feature/2026-11-23-skill-sources-map-and-search.md`。

## 方案与实现安排

1. **发现层（新模块 `agent/src/winhand/skills.py`）**
   - 一张声明式来源表，每行写清：层、宿主、位置、遍历方式。
   - 项目层：从 start 到项目根，每一层都看 `.agents/skills`、`.claude/skills`、`.codex/skills`；`.pi/skills` 只看 start。没有 `.git` 时只看 start。
   - 用户层：`~/.agents/skills`、Claude home、Codex home、`~/.pi/agent/skills` 各自的 skills 目录，或者 `[context] skills` 指定的目录。
   - 遍历方式：
     - Codex 式：收集每一个匹配，深度 6，每个根最多 2000 个目录；
     - Claude 式：只看一级。
     - 都跳过以点开头的目录和 `synced`。每次调用合计不超过 4000 个目录、2 秒。
   - 插件层：
     - Claude：`installed_plugins.json` 加上 user → project → local 三层的 `enabledPlugins`，技能入口看 `plugin.json` 或 `marketplace.json` 声明的，默认 `skills/`。
     - Codex：`config.toml` 里 enabled 为 true 的，加上带 `.codex-remote-plugin-install.json` 而且没被显式关掉的；版本优先 `local`，其次取最大版本号。
2. **身份**：
   - id 的形式是「层:相对路径」，例如：
     - `project:.codex/skills/openspec-flow`
     - `user:~/.codex/skills/officecli/officecli-docx`
     - `plugin:figma@claude-plugins-official/figma-use`
   - 同一个真实文件只出一条，`also` 里列出其他来源。
   - 裸名解析顺序：离 start 近的项目层、用户层、插件层。未受信项目的技能不遮蔽同名的用户技能。
3. **信任**：`[context] project_skills = "warn"`（默认）、`"trusted"` 或 `"off"`，另有 `trusted_roots`。
   - 被 Codex 显式标为 untrusted 的项目，项目技能一律排除。
   - warn 模式下，未受信项目的技能照常列出，并标上 `trusted: false`。
4. **宿主开关**：Claude 的 `skillOverrides` 值为 off，或 Codex 的 `[[skills.config]]` 里 `enabled=false` 时，不隐藏这个技能，只标 `host_off`。这样的技能不进地图，检索时排在后面。
5. **展示**：
   - 能力地图的文案由一个函数生成，三个出口裁剪成不同长度：
     - MCP 说明里一行；
     - 云端开场 hook 的技能段，替换现在全量平铺的约 9k；
     - `context()`。
   - `context(path)` 的 `skills` 给出这个项目的技能，10 个以内带全文描述，再加常驻技能；`skills_note` 写出带真实 path 的调用写法。
6. **检索**：
   - `skill(query=…)` 的 query 可以是字符串，也可以是 1–4 个中英文词。
   - 打分在本地做：先用内置双语别名表扩词，再按字段加权。
   - `scope` 只做软加权，当前 scope 最多占一半名额；scope 解析失败时退回全机检索，并给出提示。
   - 默认返回 10 项。只给 `domain` 时列出这个领域的技能。
   - 跨项目的结果带 `cross_project`，取正文时附一句出处提醒。
7. **报告**：`winhand skills` 输出各来源的个数、领域候选、描述过糊或没归到领域的技能、宿主开关差异，以及 winhand 日志里的使用次数。

## 验证

- 单元测试覆盖：
  - 项目链和四种目录、递归与上限、id 与去重；
  - Claude 和 Codex 插件的启用判定，包括项目级关闭、远端标记、版本选择；
  - 信任三种模式；
  - 中文检索；
  - `skill(id)`、`skill(repo, path)` 的子路径；
  - `context` 的地图与项目技能、开场 hook 的文字。
- 在本机真实验收：
  - md2visio 的根目录和 `docs`：能看到 `openspec-flow`，`context → skill` 能读回 `.codex/skills/openspec-flow/SKILL.md`。
  - Trellis 的根目录和 `packages/cli`：根目录有 `.pi` 技能，子目录没有。`.agents` 与 `.pi` 同名时 `.agents` 胜出，但两个都能用 id 取到。
  - dev-board：junction 指向同一个文件时只出一条，`close-out` 的项目版和全局版都能取到。
  - 插件：Claude 31 项、Codex 55 项，与 t18 实测一致。
  - `context()` 不传 path 时回答在几 KB 以内。
