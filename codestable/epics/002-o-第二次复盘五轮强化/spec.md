## 这条线要改变什么

依据 `docs/reviews/2026-11-17-usage-review.md`，材料包括：
- 11-02 至 11-17 的调用日志，54,259 次；
- 272 个云端会话：两任 RK3588 总调度派出的 258 个子会话，加上你自己的会话；
- 11-17 的 pi 对比讨论。

这半个月调用本身很稳，报错 0.5%。浪费在等待和重复读：
- 会话靠闹钟醒，醒一次就重读三五十万 token 的上下文；
- 规矩一次 4 万字节，还截掉了最新的授权；
- 多会话的输出互相灌进上下文；
- 换行 bug、守卫误伤逼 AI 用脚本绕路。

分五轮，每轮一个版本：

| 轮次 | 版本 | 要解决的事 |
|---|---|---|
| 第 1 轮 | 0.10.3 | 换行一对 bug；`run-N` 结果不丢；`job_status()` 列表与 `job_stop` 瘦身；`stdin_file`；回复带电脑时间；动作别名；`ALWAYS_LOAD` 按用量；守卫拒绝记出处 |
| 第 2 轮 | 0.11.0 | 任务结束叫醒会话：中转 `/hook/wait` 加沙箱后台命令，等待期间零回合 |
| 第 3 轮 | 0.11.1 | 规矩瘦身：`since` 按文件、追加只给新增、超长文件给目录加最新部分 |
| 第 4 轮 | 0.12.0 | 多会话与离线：常驻任务重启后拉起、断线更早发现、任务状态更准、负载信息、读文件不挡别人改名 |
| 第 5 轮 | 0.12.1 | 守卫与安全：只看命令位置、内置保护登录信息；第七节定下的密码管理器和暂存清理 |

## 当前怎么理解（活规格）

- **硬约束是主人的 Claude 额度，不是调用延迟。**
  - 11-07 额度用完，各线停了约四天。
  - 子会话上下文常到 30–60 万 token，一次醒来的花费约等于重读一遍上下文。
  - 所以每一轮都先问：这能省掉多少回合、多少字节。
- **不改现有参数的含义。** 经中转每次最多等 40 秒这条不动，叫醒是另开的一条路。`.agents/notes/implemented/feature/2026-11-01-relayed-calls-wait-40s.md` 记着为什么是 40 秒。
- **叫醒走中转的 `/hook/`，不走电脑登录、不走 GitHub。**
  - 你 11-01、11-07 两次说过只在网页端用 Claude，电脑上不登录。
  - GitHub 信箱实测能叫醒（14 秒），但要会话挂仓、要你本人批准开 PR，票上一直没开。
  - 沙箱代理已经放行 `/hook/`，还自动带上令牌。这个令牌只开 `/hook/*`，到不了 `/mcp`、一次性链接和 `/agent`。
  - 叫醒只回状态（结束没有、退出码、匹配到什么），不回输出。
- **一个会话的输出不进另一个会话的上下文。** 列表只给状态行；大输出要按游标去取，不顺带塞给别人。
- **规矩宁可少给，也不能悄悄截掉最新的。** 截了就说截了什么、去哪儿读。
- **守卫只收不放。** 减少误伤，靠更准地认出命令，不靠放宽规则；你的「禁止批量删除」不变。

**候选质量目标（还不是承诺，第 2、3 轮实测后定）：**
- 被等的任务结束到会话醒来：p90 ≤ 1 分钟。现在的上界是 15.7 分钟。
- 每个被等的任务问 `job_status` ≤ 1 次，`send_later` 回访次数降一半以上。
- 每个子会话收到的规矩字节数降一半以上。
- 第 1 轮以后，`run-N` 结果「no running command」为 0。

**要你定（复盘第七节，不定也不挡别的轮）：**

1. 暂存目录清理：属于批量删除。建议 14 天没动、没放 `.keep` 的，移到回收站，先列清单。
2. 电脑回来后要不要等你一句才接着干。建议计划内的照旧等你，计划外断线自动接上。这是 rk3588 的规矩，不是 winhand 的代码。
3. 密码管理器窗口：建议默认不截图、不点，要用时一次一放。
4. rk3588 CLAUDE.md 的授权一节：建议原文挪到单独文件，CLAUDE.md 只留现行规则。

**暂不推进 / 未确认：**
- 第二台常开的电脑或多机：要你先决定加不加机器。
- MCP tasks 进云端会话、连接器放开 60 秒：出现了再实测。
- GitHub 信箱：第 2 轮做通后，巡检通知改走叫醒命令，旧总调度不必再留着转发。由总调度按第 2 轮的结果定。

- 和 pi 的关系（11-17 两个会话的结论一致，不换 pi）：
  - winhand 的工具接口不改成 pi 的形状。pi 插件跑在 pi 的进程里，不消费 MCP 的工具，改了也用不上。
  - 真要让 pi 用这台电脑，就写一个 pi 扩展，经 pi 的 Operations 接口把 I/O 转给 winhand。
  - 「少数常驻、其余按需」winhand 已经在做，只是名单要按用量改（第 1 轮）。
