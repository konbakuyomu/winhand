# 第 4 轮（0.12.0）：多会话与离线

## 做成以后是什么样

1. **常驻任务**：`job_start(..., keep=true)`，给排队程序这种要一直跑的程序用。
   - 电脑重启、睡眠唤醒或 winhand 自己起来时，没正常结束的常驻任务自动重新拉起；
   - 同名的常驻任务只留一个；
   - `job_stop` 以后不再拉起。
2. **断线更早发现。** 连接已经死了的时候，比客户端的 60 秒更早发现，正在执行的调用尽快续上，或者给出写明原因的报错，不再连着报「timed out after 60s」。
3. **任务状态更准。**
   - 天生安静的任务可以设 `quiet_ok_s`，不再被报「卡住」；
   - 被 `timeout_s` 结束的，在列表和状态里写明「超时（6 小时）」；
   - `run` 里的程序没起来（例如命令行太长）时，不报退出码 0。
4. **负载信息。** `sys_info(load=true)` 给可用内存、CPU、正在跑的任务数；`proc_list` 能按命令行筛。
5. **读文件不挡别人改名。** `fs_read`、`fs_search` 等在 Windows 上打开文件时允许共享删除（FILE_SHARE_DELETE），别的程序「写临时文件再改名」不会因为 winhand 正在读而失败。

**范围：**
- 不包含：排队程序自己的逻辑（它在 dev-board 里），以及第二台电脑。

## 为什么现在做

复盘第四节第 2、4、10 条：
- 排队程序活不过重启和睡眠，靠每 10 分钟巡检拉起：6 天 717 次。
- 11-12 旧总调度连续 8 次 60 秒超时，没有快速报错，最后只好整个交接。
- Colab 驱动被误报卡住；超时结束的作业 `reason` 为空；`run` 假成功一次。
- AI 用 `Get-CimInstance` 查内存定 Codex 名额，6 次。
- 排队程序改名 `queue.json` 报 EPERM 崩过一次。`fs.py` 75 行用 Python 的 `open`，不带共享删除。

## 方案与实现安排

- **常驻任务**：
  - 在任务目录记 `keep`；
  - winhand 启动时、收到系统唤醒（`WM_POWERBROADCAST`）时，扫一遍 vanished 的常驻任务，按原命令重开，新开的记一条 activity；
  - 每次重开间隔不小于 1 分钟，免得一直崩、一直拉。
- **断线**：先查 11-12 那 13 分钟里电脑和中转各自看到了什么（中转日志、`activity` 的 connection 记录）。
  - 如果是连接已死而心跳还没发现：把 keepalive 判死的时间压到 30 秒以内；
  - 中转那边，连接被替换时，正在执行的调用立刻转给新连接，或者快速报错。
- **共享删除**：读文件统一走一个打开函数。Windows 上用 `CreateFileW` 打开，带 `FILE_SHARE_READ | WRITE | DELETE`，再转成 Python 文件对象；其他平台照旧。

## 验证

- 单测：
  - 常驻任务被杀后，模拟一次启动，会被拉起，而且不重复；
  - `quiet_ok_s` 生效；
  - 超时原因出现在列表里；
  - 命令行太长时报错。
- Windows 场景测试：一边用 `fs_read` 读着，一边让另一个进程 `os.replace` 这个文件，替换成功。
- 装到电脑上实测：
  - 重启电脑，排队程序在 1 分钟内回来；
  - 合上盖子再打开，看常驻任务和 activity 记录。
- 一周后看巡检日志：它重开排队程序的次数应为 0。
