# 第 5 轮（0.12.1）：守卫与安全

## 做成以后是什么样

1. **守卫只看命令位置上的词。** 规则照旧，认法更准，「禁止批量删除」一条不松：
   - 引号里的搜索模式不再被当成删除命令：`Select-String -Pattern '…|rm'`、`-Pattern '…rmtree'`；
   - Python 代码里叫 `ri` 的变量也不算；
   - 删一个已经空了的目录（不递归）不算批量删除；
   - 其余的照旧拦。
2. **内置保护常见的登录信息。** 读、搜、打包、下载都拒，像 `secrets.env` 那样，不用主人自己写规则：
   - 浏览器的用户数据目录；
   - gcloud、Colab、gh、npm 的登录文件；
   - `.netrc`、`*.pem`、`id_*` 私钥；
   - 用 `USERPROFILE` 指过去的「登录用配置目录」（例如 `scratch\t127\colab-acct2`）。
3. **按复盘第七节你定的：**
   - **密码管理器窗口**（第 3 条）。建议的做法：1Password、Bitwarden、KeePass 等窗口默认不截图、不输入；要用时在托盘里对这一次放开。
   - **暂存目录清理**（第 1 条）。建议的做法：每周把 14 天没动、没放 `.keep` 的文件夹列成清单，你在托盘里点一下，才移到回收站。不跟联接点，只删联接点本身。

**范围：**
- 不包含：替主人改 `guards.toml` 的规则内容。
- 第 3 项要等你定，不定就只做 1、2。

## 为什么现在做

复盘第四节第 6、7、8 条：
- 3 次确认的误伤，AI 只好把代码挪进文件再跑。
- 拒绝日志只到 500 字，看不清触发点（第 1 轮已补记出处）。
- 暂存目录 22 GB，里面有：
  - Google 登录，现有规则管不到；
  - 封存的考题名单，不能按时间删；
  - 指向工作区的联接点。
- 11-17 有一段操作把 1Password 当目标 116 次、截图 211 张，截图会把窗口内容原样交给模型。

## 方案与实现安排

- **守卫的认法**：
  - 对 PowerShell 脚本先去掉注释和字符串字面量，再匹配「命令位置」上的词：行首，以及 `|`、`;`、`&` 之后；
  - 路径参数照旧带着通配判断，所以 `Remove-Item "$d\*.py"` 仍然拦；
  - Python 脚本只认真正的删除调用：`shutil.rmtree`、`os.remove` 在循环里、`Path.unlink` 配通配，不看变量名。
  - 改之前，把 11-02 至 11-17 被拒的 32 条（取得到全文的）和误伤的 3 条做成回归用例，先跑一遍，确认只放掉误伤。
- **登录信息**：作为内置规则（`winhand (built in)`）列进 `context()` 的守卫一节，主人看得见。
- **密码管理器**：按窗口所属的程序认，不按标题。

## 执行记录（2026-11-17）

1. 守卫的认法：提交 `58c1ddf`，和方案有出入。
   - 没有对整段脚本去掉字符串、再找命令位置，只把搜索命令的模式参数换成 `x`：`Select-String -Pattern`，以及 `rg`、`grep`、`findstr` 的模式和 `-e`。改动面小，误放的可能也小。
   - 双引号里带 `$(` 或反引号的照旧看；`rg --pre` 之后的照旧看（审查时补上的，`--pre` 会对每个文件跑程序）。
   - Python 里叫 `ri` 的变量：没做。动作里不带语言信息，分不出是 Python 还是 PowerShell。
   - 删一个空文件夹：本来就不算批量删除（不递归的 `fs_op delete`），只在 `help()` 和 README 里写明。
   - 回归用例：放行的是 3 条误伤和 6 种同类写法；照旧拦的有 11 条，含 `rg --pre`、`$(…)`。32 条历史拒绝里取得到全文的那部分，没有逐条做成用例，留到装上后用 `activity_stats.py` 对照。
2. 登录信息：内置第 7 条。
   - 管到：colab、gcloud、git、docker、gh 的登录文件，`~/.ssh` 私钥，三种浏览器的用户资料，1Password 本地目录。
   - 没放进去的：`.npmrc`（项目里常有，内容多半是源地址，令牌靠输出脱敏）、`*.pem`（证书也是 .pem，太宽）。
   - 规矩文件引用这些文件时，主人批准了外部引用也不读；两个老测试为此改了断言。
3. 密码管理器（第七节第 3 条）：提交 `bb4ee5c`。按程序名认，程序授权关着也问，放开只管 10 分钟。审查时补上：`ui` inspect 和截图一样要先放开。
4. 暂存目录清理（第七节第 1 条）：提交 `bb4ee5c`，和方案的出入是审查时补的四处。
   - 数大小一共只花 3 秒，不是每个文件夹 3 秒：200 个文件夹会数十分钟。
   - 屏幕锁着时不问，也不算问过。
   - 弹不出对话框时，一小时后再试。
   - 回收站的标志加了 FOF_WANTNUKEWARNING：照 Windows 文档，不加它时，回收站装不下的东西会被直接永久删掉。`fs_op` 的删除也受益。
