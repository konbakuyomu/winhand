# Windows 操控：控制会话与人机共用

> **读者：** 接手这条改进线的人：相对 0.13.0 要改什么，现在怎么理解方案，哪些能推，哪些还悬着，关了以后合回哪里。

---

## 这条线要改变什么

2026-11-24 主人说，用了很长时间下来，Windows 操控是 winhand 最大的短板，点了三处：

- 没有明确的信号和机制，表示 AI 正在控制电脑；
- AI 不能和主人同时用电脑。ChatGPT 的 computer use 会给几个标签页标上「正在控制」，只在那几页里操作；
- 不能只控制某个程序。ChatGPT 有局部控制、全局控制，也有退出全局控制的办法。

主人要求「务必要测试加讨论决定好之后再开始推进」。当天在主人电脑上试了 CUA 驱动，又让 winhand 和它在同样的窗口上做配对实测，在 parley 房间 t30 讨论了五轮。主人拍板选 B：照着 CUA 的做法在 winhand 里自己写。取舍和被否的方案见 [决定笔记](../../../.agents/notes/implemented/architecture/2026-11-24-windows-control-own-backend.md)。

相对现在：

| | 现在（0.13.0） | 这条线做完 |
|---|---|---|
| 主人正在用电脑 | AI 的桌面动作先等主人停手，最多 10 秒，然后放弃 | AI 在后台操作被允许的窗口，主人照常打字，输入不被抢走 |
| 后台操作 | `ui` 的控件操作会把目标窗口拉到前台：实测主人打字时每轮抢 2 次；`input` 每次都强行拉前台 | 两招守卫让后台动作不抢焦点；做不到就明说，经主人批准才借用前台 |
| AI 在操作的信号 | 动作时屏幕四周一圈橙框，最后一个动作 2 秒后消失 | 控制期间一直亮：目标窗口的边框、托盘状态；全局控制或借前台时再加横幅 |
| 允许 AI 动哪里 | 按程序授权，一个程序的所有窗口一起放开 | 控制会话：窗口、程序实例、标签页、全局四档 |
| 停下 | Ctrl+Alt+Shift+Backspace 急停 60 秒 | 暂停和继续、硬停；借前台时按 Esc 也能停 |
| 浏览器 | 当普通窗口操作 | 主人拖进「AI · winhand」标签组的标签页，AI 才能动 |

关联的现状规格：
- `codestable/spec/desktop.md`：程序授权、主人在电脑前时（让路、急停、边框）、截图、操作不了的情况。这几节都会变。
- `codestable/spec/index.md`：统一语言里要加「控制会话」。

## 当前怎么理解（活规格）

### 为什么自己写，不接 CUA 驱动

CUA 驱动（trycua/cua 的 Windows 驱动，MIT）在主人电脑上，后台点击、写值、取被挡住的窗口都做得到。但主人最要的东西它都不管：信号、范围、停止、标签组、密码管理器保护、程序授权，这些都得写在 winhand 里。它自己的后台操作也不全对：后台 Ctrl+A 会输进字母 a；偶尔会抢焦点；启动商店程序时回的是共用的宿主进程号。维护也重：约 82 MB；预发布版一天发好几个；接口提前两天通知就删；遥测默认开。它真正值得学的是两招防抢焦点，约 30 行，用 Python 写出来效果不比它差。

### 后台操作不抢焦点：两招守卫

实测查明，UI Automation 的控件操作本身就会抢焦点，不是 winhand 自己的代码在拉前台：
- 写经典编辑框的值，会把那个窗口切到前台；
- XAML、UWP 和 Chromium 程序在处理「点击」时，会自己把自己拉到前台。

两招守卫，每个后台动作都套上：

- **不可激活**：动作期间给目标的顶层窗口加 `WS_EX_NOACTIVATE`，做完只去掉这一位。所有程序都套。
- **临时禁用**：对 XAML、UWP、WinUI、Chromium、Electron 宿主，在点击、切换、选择、展开、写值的调用期间禁用它的顶层窗口，调完恢复原状态。被禁用的窗口当不了前台，调用照样送达。

**必须守住：**
- 任何结束路径都还原窗口：正常返回、被拒、异常、超时、急停。超时的 UIA 调用可能还在程序里执行，守卫要等它返回再撤，但要设上限，不能让主人的窗口一直是灰的。
- 只改目标窗口自己，绝不碰主人的前台窗口。
- 别的虚拟桌面上的窗口不加样式。
- 以管理员身份运行的窗口照旧拒绝。

**挡不住的：** WPF 程序的控件在点击、写值时同步调 `UIElement.Focus()`。要挡住，得有一个签名、装进系统目录、带 UIAccess 的辅助进程。第一版遇到 WPF 时先说明，再请主人批准借用前台。

**已落地（第 1 张票，2026-11-25 关闭）：**
- **覆盖范围**：`ui` 的五处后台动作都套了守卫：投递点击、UIA 模式调用、PowerShell 退路、写编辑框、滚动到可见。`window` 的最小化、还原、最大化、移动，目标不在前台时也不再把它切到前台。
- **实测**：
  - 主人在记事本里打字时，winhand 做了 90 个动作，包括点灰掉的按钮，前台变化 0，注入 0。改之前同样的测试，每轮抢 2 次。
  - CI 的 Windows 机器上，「记事本在前台时操作测试窗口」的场景通过。
- **超时**：守卫等调用真正返回再撤，最多 30 秒。
- **样式加不上时**：照常做，不报错。加不上的只有以管理员身份运行的窗口，现有规则本来就拒绝它们。
- **崩溃恢复**：winhand 在守卫期间退出时，目标窗口可能停在禁用或不可激活状态，关掉那个程序再打开即可。启动时自动还原留作后续切片。
- **WPF**：结果里带 `focus_note`，第 2 张票据此让这类窗口继续让路。

### 后台动作和让路

两招守卫验收以后，经守卫执行、不碰前台的后台动作，不再等主人停手。
- `input` 的按键和坐标点击，本质上是往前台送输入，照旧让路。
- 后台不能发 Ctrl、Alt 组合键：投递的组合键程序认不出来，CUA 就把 Ctrl+A 变成了一个 a。事先拒绝，或请主人批准借用前台，或改走 UIA 的快捷键。
- 主人正在操作的就是 AI 的目标窗口时，AI 暂停（第三轮 m275）。

**已落地（第 2 张票，2026-11-25 关闭）：**
- **规则**：前台窗口属于别的程序、目标不是 WPF 时，`ui` 的控件动作算后台动作，只查急停，不等主人停手。判断在 `desktop.background_ok`。
- **照旧让路的**：
  - 前台就是目标的程序：主人在用它；
  - WPF 程序；
  - `input`、`window`、`ocr` 的点击；
  - 后台动作里退回前台真点的那一步，以及 `steps` 里的 `keys`、`type` 步：这一串还没等过主人的话，在那一步等一次。
- **实测**：主人在记事本里打字的 42 秒里（按键 667 次），AI 经完整的 `ui` 工具做了 84 个动作：「这人正在用电脑」的拒绝 0 次，前台变化 0，注入 0，结果全对。改之前，主人一动键盘，这些动作就等满 10 秒后放弃。
- **还没分开的**：所有商店程序共用一个宿主进程，主人在用任何商店程序时，AI 操作商店程序也会等。

### 控制会话（第三轮 m275）

- **范围四档**：标签页、窗口、程序实例、全局。
  - 授权绑定在「客户端 + 窗口句柄 + 进程实例」，或「标签页 + 站点 + 读写」上；程序级的「一直允许」不自动扩到会话。
  - 「在哪里操作」和「借用前台」分开批。
- **生命周期**：申请 → 进行中（操作中、思考中）→ 暂停 → 结束。断线、超时、撤权以后旧会话作废，恢复要主人操作。
- **信号**：
  - 一直亮到会话结束，包括 AI 思考的时候；
  - 能穿透点击，不出现在截图里；
  - 后台局部控制：目标窗口的边框，加托盘状态；
  - 全局控制或借前台：屏幕边缘发光，加顶部横幅，写明目标、状态和怎么停。
- **停下**：
  - Ctrl+Alt+Shift+Space 暂停或继续；
  - Ctrl+Alt+Shift+Esc 和原来的 Backspace 都是硬停；托盘也能一键停；
  - Esc 只在借前台或全局控制时拦截；
  - 碰到登录、支付、密码、验证码，转成暂停，请主人接手。
- **后台做不到时**：回 `BACKGROUND_UNAVAILABLE`；窗口被挡住取不到图时回 `CAPTURE_OCCLUDED`，并告诉模型控件树还能读。借前台要同时满足四条：主人批准；主人停手 1.5–2 秒；亮横幅并挂 Esc 钩子；做完把原来的前台还回去。

### 工具怎样对模型更省、更不容易错（第一、二轮 m267）

- **观察结果带 `view_id`**，绑定客户端和会话。发输入前核对窗口、控件身份和焦点，变了就不发。
- **短表**：首屏约 100 项，带 `scanned`、`retained`、`shown`、`truncated`。
- **动作以后**：回 diff；批量动作默认不截图。
- **效果回执**：分「确认生效」「没变化」「已发送、待核验」。已经送进程序的动作，不算「后台做不到」，防止模型换前台重试、做两次。
- **说明重写**：改写 GUIDE 和 GUIDE_FULL。

### 浏览器（第三轮 m275）

做一个薄的 MV3 扩展：`tabGroups` 加 `chrome.debugger`，经 Native Messaging 连 winhand，给模型 4–6 个工具。
- 只动主人点选或拖进组的标签页；没进组的标签页，连标题也不上报。
- 拖出标签组 300 毫秒内撤权。
- 跨站导航要另批；同源新开的标签页自动入组。
- 不连主人整个浏览器的远程调试：Chrome 136 起默认目录不认 `--remote-debugging-port`；Chrome 144 起的开关会连上整个浏览器，每次连接都弹窗，还一直有横幅。

### 质量约束

- **交互能力（用户参与、用户差错防御）**：主人在前台打字时，AI 的后台动作不改变前台、不注入任何键鼠，主人打的字逐字不变。
  - 来源：主人 11-24 的要求和实测。
  - 证据：「主人输入不受影响」验收题，带每 5 毫秒的前台轮询和低级钩子。
- **交互能力（用户参与）**：主人按暂停或停止后，100 毫秒内不再发出后续输入。已发出的动作标「已发送、待核验」，不自动重试。按钮先计数加一再弹框的测试里，计数恰好是 1。
- **信息安全性（保密性）**：工具的回复里，不出现授权范围以外窗口的标题和图像。按窗口取图失败时，不退回去截屏幕上同一块地方的像素。
  - 已落地（第 3 张票，2026-11-25 关闭）：新窗口只报目标拥有的，其余只计数；`steps` 遇到目标不拥有的窗口就停（`UNEXPECTED_DIALOG`）；按窗口取图失败或全黑时回 `CAPTURE_OCCLUDED`。
  - 证据：主人电脑上 11 项验收全过。改之前的 0.13.0 截一个不让截图的窗口，回的是它下面的窗口，OCR 读出了标记。
- **可靠性（可恢复性）**：守卫在任何结束路径上都把窗口还原成动作前的启用状态和样式。winhand 中途崩溃的情况，实现时定一种恢复办法。
- **第一、二轮定的门槛**（m267）：错窗输入 0，敏感内容落盘 0，成功率不降，token 中位数降 30%。

### 术语（本 Epic 内）

- **控制会话**：AI 在一个范围里操作的一段时间，有开始、暂停、结束，信号一直亮。
- **后台动作**：不经前台、不发系统输入就送进程序的动作，比如 UIA 的模式调用、投递消息。和它相对的是借用前台。
- **两招守卫**：不可激活守卫和临时禁用守卫的合称。

## 现在推什么、先搁什么

**可推进：** 三张票都已关闭：第 1、2 张随 0.14.0 发布，第 3 张等桌面端 UI 改版一起发 0.15.0。下一步按顺序做下面的切片，先是控制会话的底座。

**Issues：**（都在同目录 `issues/` 下，编号只在本 Epic 内有效）

- [x] `issues/001-x-后台操作不抢焦点.md` — 两招守卫和防抢焦点回归。主人电脑上 90 个动作前台变化 0，CI 的 Windows 场景通过。
- [x] `issues/002-x-后台动作不再等主人停手.md` — 经守卫执行的后台动作不再让路。主人打字时 84 个后台动作，拒绝 0、前台变化 0。
- [x] `issues/003-x-止血不回传无关窗口.md` — 新窗口只报目标拥有的；按窗口取图和 OCR 不退回屏幕像素；`steps` 遇到不归属的窗口、切前台失败都停。主人电脑上 11 项验收全过。

**定了方向，还没建票的切片**（按顺序）：
1. 控制会话的底座：范围、生命周期、授权绑定、撤权；
2. 信号和停止：目标窗口边框、托盘、横幅、暂停和硬停，以及 `hold_key` 能被打断；
3. 工具契约：`view_id`、短表、diff、效果回执、改写说明；
4. 浏览器标签组扩展，先花半天测 Chrome 和 Edge 上的标签组事件和撤权。
5. 守卫的崩溃恢复：加守卫前记下窗口，winhand 启动时还原上次没撤掉的。现在的办法是关掉那个程序再打开，见第 1 张票的关闭结论。

**暂不推进 / 未确认：**
- **WPF**：要签名的 UIAccess 辅助进程。第一版先说明，再借前台。
- **WGC 取图**：Chromium、Office 窗口被挡住时截出黑图，才加，另计 2–4 人日。
- **Office COM**：放在标签组扩展之后。
- **AI 自己开程序**（不抢焦点地启动）：第一版只操作主人已经打开的窗口。CUA 的启动会盖住主人的其他窗口；启动商店程序时回的是共用的宿主进程号。这两点要先想好再做。
- **本机 MCP 网关的授权请求串会话**（m267 第三条）：单独修，不在本 Epic。
- **密码管理器的三处漏洞**：在 Epic 002 第 7 张票，不在这里重复。

**工作量**：只操作主人已打开的窗口，14–24 人日（codex-c 估）；AI 自己开程序，16–27 人日。

**关闭时要满足：**
- 三张票和上面四个切片都做完，第一版范围内的验收题在主人电脑上逐题跑过。验收题：
