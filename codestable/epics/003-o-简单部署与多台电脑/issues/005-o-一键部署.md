# 一键部署

## 做成以后是什么样

- README 的「部署中转」只剩两种做法：
  - Cloudflare：点「Deploy to Cloudflare」按钮，填主人口令；国内再在控制台给 Worker 加一个自定义域名。也可以先 Fork 再从 Cloudflare 导入，以后同步 Fork 就自动重新部署。
  - 自己的服务器（Linux 加 Docker）：一条命令。它问域名和主人口令，起 workerd 和 Caddy，Caddy 自动申请证书，最后打印首页地址。
- 部署完打开首页，按 003 的三步接入。

## 方案

- `relay/wrangler.jsonc`：
  - KV 保留默认 id，按钮会建好并替换成新的；
  - 去掉 `PUBLIC_ORIGIN` 的空值，代码里取请求的地址。
- `relay/.dev.vars.example`：只写 `OWNER_PASSPHRASE`。`AGENT_TOKEN`、`HOOK_TOKEN` 是可选的，不放进去，因为按钮会把这个文件里的每一项都当成必填。
- `relay/package.json` 加 `cloudflare.bindings.OWNER_PASSPHRASE.description`。
- CIMD 默认关，变量 `CIMD=on` 才打开（原因见 Epic）。
- 自托管：
  - `relay/selfhost/install.sh`：检查 Docker，生成或询问密钥，写进只有 root 能读的文件，`docker compose up -d --build`；
  - Caddyfile 用环境变量里的域名。
- 文档：
  - README 的三节改写；
  - `docs/relay.md` 的部署和地址部分；
  - `codestable/notes/001-发版与部署.md`。

## 风险

- claude.ai 在 CIMD 关掉时是否走动态注册。仓库里的中转从一开始就开着 CIMD，没有现成证据。验证办法：主人在 claude.ai 添加新的 `/pc/<名称>/mcp` 连接器。不通就在 LAX 设 `CIMD=on`，并在文档里写明 Cloudflare 在受限地区的限制。
- Deploy 按钮只能在浏览器里点。能做的是用主人的 Cloudflare 令牌，按同一份配置部署一个测试 Worker，跑通授权和调用；按钮本身请主人点一次。
- 自托管的一条命令要一台真 Linux 加 Docker 才能完整验证。云端沙箱里没有 Docker，只能验证脚本生成的配置；真机验证写明尚未做。

## 验证

- `wrangler deploy --dry-run` 通过；测试 Worker 部署以后，用脚本走完注册、授权、换令牌、调 `tools/list`；
- `install.sh` 的生成部分做单元测试；能拿到真机时再完整跑一次；
- README 的每一步对着实际页面走一遍。
