# 中转支持多台电脑

## 做成以后是什么样

- 一个中转连多台电脑，每台电脑的东西都在 `/pc/<名称>/` 下：`mcp`、`mcp/<服务>`、`agent`、`t/<令牌>`、`hook/<事件>`、`status.json`。
- 每台电脑：
  - 有自己的设备令牌（中转只存哈希）；
  - 有自己的 Bridge（`pc:<名称>`）；
  - 有自己的 OAuth 资源 `https://<域名>/pc/<名称>/mcp`。
- 给一台电脑签的 OAuth 令牌，调不了另一台。
- 有 `AGENT_TOKEN` 时，旧地址 `/mcp`、`/agent`、`/t/`、`/hook/`、`/status.json` 都指向 `default` 这台；旧连接器的登录不失效。
- agent 的链接前缀取自己的连接地址去掉 `/agent`：旧地址得到 `https://<域名>`，新地址得到 `https://<域名>/pc/<名称>`。

**范围：** 不包含页面、配对和安装（003、004）。这张票里，电脑只能靠 `AGENT_TOKEN` 或测试里直接写进 KV 的令牌连上来。

## 现状怎么工作

- 中转只有一个 Bridge：`relay/src/index.ts` 的 `bridge()` 固定用名字 `default`。
- `/agent` 只认 `AGENT_TOKEN`。新连接会把旧连接以 4000 关掉，电脑收到后不再重连（`relay_client.py` 的 `Replaced`）。
- OAuth 用 `OAuthProvider`，只有一个资源 `${origin}/mcp`，`apiRoute: "/mcp"`；本机其他服务 `/mcp/<名称>` 共用这个资源。
- agent 的链接前缀只取中转地址的 origin（`transfer.py` 的 `set_relay`，`session_bridge.py` 的 origin）。

## 方案

- **路由**，新模块：
  - 解析 `/pc/<名称>/<其余>`；
  - 旧地址在有 `AGENT_TOKEN` 时映射成 `default`；
  - 名称不合法、电脑不存在时回 404，不泄露有哪些电脑。
- **电脑清单**存在 KV：`winhand:pcs` 存名称列表和加入时间，`winhand:pc:<名称>` 存令牌哈希。读清单失败时回 503，不当成空清单。
- **OAuth**：
  - 授权服务器改用 `OAuthAuthorizationServer`，资源清单是 `pcs.map(/pc/<名称>/mcp)`，有 `AGENT_TOKEN` 时再加上旧的 `${origin}/mcp`；每个请求按当前清单构造。
  - 每台电脑的 `/pc/<名称>/mcp` 交给一个 `OAuthResourceServer`，由它校验令牌的 audience。
  - 授权页从请求的 `resource` 认出是哪台电脑，页面上写明；`props` 里记下电脑名。
  - 旧的 `OAuthProvider` 存在 KV 里的登录，按同一个库的格式继续认，迁移期间不用重新授权。这一点要在穿刺里验证。
- **Bridge**：按名字取 `pc:<名称>`。Bridge 内部不改；离线提示里的 `status.json` 地址改成那台电脑的。
- **hook 和链接**：路径正则改成匹配 `<其余>` 部分；失败计数照旧按 IP。
- **agent**：`public_base()` 和 hook 用的地址都取连接地址去掉末尾的 `/agent`。

## 风险与穿刺

1. 授权服务器按请求构造、带多个资源：能注册、授权、换令牌、刷新，拿着令牌能调自己那台、调不了别的。用 workerd 真实运行时测试来证。
2. 旧 `OAuthProvider` 签的令牌和登录，换成新类以后还认：在运行时测试里先用旧代码签一个，再换新代码去调。
3. 每个请求都构造授权服务器的开销：看 CPU 时间；太高就按清单的版本号缓存。

## 验证

- 单元测试：
  - 路由解析，包括旧地址映射、非法名称；
  - 令牌哈希比对；
  - agent 的链接前缀。
- 运行时测试：
  - 两台电脑同时连上，各自调到自己，交叉调用被拒；
  - 旧地址和旧登录照常；
  - 移除 `AGENT_TOKEN` 后旧地址 404。
- relay 原有测试、agent 测试全过。
