# 守卫补上批量删除的漏洞

复盘时发现，你的“禁止批量删除”规则（`~/.winhand/guards.toml` rule 1）有几种写法能绕过，`fs_op` 也能把整个文件夹删进回收站。11-01 按建议补上，规则文件的改动由你在电脑上点了确认。

- 改动：`agent/src/winhand/actions.py` — `fs_op(action="delete", recursive=true)` 除了按 delete 判断，还按 `command` 判断，看成 `Remove-Item -Recurse -LiteralPath '<路径>'`，原来写给命令的 rule 1 因此也管得到它。
- 改动：电脑上的 `~/.winhand/guards.toml`（不在仓库里）：
  - rule 1 补上 `rd/rmdir/del/erase` 的 `/s` 不在第一个参数、`[IO.Directory]::Delete`、Node 的递归删除和 `rimraf`、`ForEach-Object`/`%`/`foreach` 循环里的删除；
  - 新增 rule 4：`robocopy` 带 `/MIR` 或 `/PURGE` 先问你。
- 改动：`README.md` 守卫一节写明 `fs_op` 整个删文件夹怎么判断。
- 验证：
  - 新规则先在沙箱里对 22 种该拒绝的写法（含原来就挡住的）和 22 条普通命令跑过：该拒绝的都拒绝，普通命令一条也没误伤。
  - 装上以后，在电脑上用不存在的路径探了两种原来能绕过的写法（`rd /q /s`、`[IO.Directory]::Delete`），都被 rule 1 拒绝；`git log` 照常运行。
  - `agent/tests/test_review_round4.py::test_deleting_a_whole_folder_is_judged_like_remove_item_recurse`：整个删文件夹被命令规则拒绝、文件夹还在，单个文件照常删除。
- codestable：无影响（规则文件是你的，不在仓库里；`fs_op` 的判断方式写进了 README）。
