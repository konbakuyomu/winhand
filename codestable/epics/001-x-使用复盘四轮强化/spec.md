# 使用复盘后的四轮强化

> **读者：** 接手这条改进线的人——相对 0.7.3 要改什么、现在怎么理解方案、哪些能推、哪些还悬着、关了合回哪里。

---

## 这条线要改变什么

依据 `docs/reviews/2026-11-01-usage-review.md`（09-26 至 11-01 的调用日志、10-19 至 10-31 的 66 个云端会话、Smart Search 调研），补上 AI 在 WinHand 上被迫绕路的地方。分四轮，每轮一个版本：

| 轮次 | 版本 | 要解决的事 |
|---|---|---|
| 第 1 轮 | 0.7.4 | 读文档丢正文的 bug；轮询回复瘦身；开场说明补 `remote_run`、`fs_send`、提交信息的写法；`run` 编号与几个小参数 |
| 第 2 轮 | 0.8.0 | 长任务不用守着：长等待加进度、工具注解、防休眠、后台任务加强、中转状态 |
| 第 3 轮 | 0.9.0 | 文件进出电脑和服务器：多文件与文件夹传输、大文件分片、暂存目录、一次处理多个目标的文件工具、`context` 简要模式、`remote_run` 补齐 |
| 第 4 轮 | 0.10.0 | 桌面：`input` 补全、`ui` 与 OCR 小改、控件 `ref` 与批量、主人在场、命令被弹窗卡住时提醒 |

关联 spec：关闭时已把稳定结论写进 `codestable/spec/`，见文末「关闭」。

## 当前怎么理解（活规格）

- **不改现有参数的含义。** 新能力用新参数或新取值打开。Claude Code 以外的客户端保持旧行为，例如等待的 40 秒上限。
- **等待。** 文档说 Claude Code 对远程 MCP 只限首字节 60 秒，之后有进度就一直等（`code.claude.com/docs/en/mcp`，2026-11-01 核对）。但 11-01 实测：云端会话经 claude.ai 连接器的调用到 60 秒就被切断，进度通知也没用。所以经中转来的调用每次最多等 40 秒，按游标接着问；只有这台电脑上的客户端在接收进度时才能等到 1800 秒（0.10.1）。
- **只读标记与长等待同一版上线。** 标了 `readOnlyHint` 后，同一轮里的几个 `job_status` 会同时返回，AI 现在“一轮连发 3 个等 2 分钟”的做法就不灵了。
- **防休眠由任务自己持有。** 用 `SetThreadExecutionState`，任务结束即释放；winhand 重启不影响已经在跑的任务；`config.toml` 可以关掉。
- **WinHand 自己不做的事。** 发版、部署中转、改用户电脑上的守卫规则，都要用户在电脑上确认。
- **多个文件走一个链接，不改中转。** 文件夹边打包边下载；上传的压缩包全有或全无地解开；大文件每片一个普通的一次性链接。逐个文件的规则判断（`guard.PathCheck`）搜索、下载、解开三处共用。见 `.agents/notes/implemented/feature/2026-11-01-files-through-one-link.md`。
- **人在电脑前时，桌面操作给人让路。** 人停手前先等，有急停键，AI 操作时有不进截图的边框；`[desktop]` 可以关掉。命令被别的程序的签名、登录窗口卡住时说出来，并让那个窗口闪烁。见 `.agents/notes/implemented/feature/2026-11-01-desktop-gives-way-to-owner.md`。

**已定（2026-11-01，用户要求按建议推进并直接用到电脑和服务端）：**

- **防休眠**：保持“任务、命令运行期间不睡，结束后恢复，可在 `config.toml` 关闭”，接电源和用电池一样。依据：这台笔记本接电源时本来就不睡（`powercfg`：交流 0 秒），只在用电池时 10 分钟后睡；电量到临界值时 Windows 仍会休眠，耗不光电。
- **暂存目录**：不自动清理。依据：C 盘还剩 539 GB，`~/.winhand` 全部约 41 MB；你的规矩禁止批量删除。
- **守卫规则补丁**：已补，见 `issues/005-x-ff-守卫补上批量删除的漏洞.md`。
- **桌面**：截最小化窗口不弹授权；停手 5 秒才算不用了；急停后 1 分钟内拒绝桌面操作。都保持现状。

**暂不推进 / 未确认：**

- 本机 stdio 客户端的长等待还没实测。
- 电脑离线时立即报错：还没有机会实测。
- 第 2 轮方案里没做的两项：离线时由中转代答 `tools/list`（中转要解析 MCP，和“只转发”的设计相反）；把真正的失败标成错误（所有返回 `{"error":…}` 的工具都会在客户端变成抛错，影响面太大）。
- 第 3 轮：长路径、联接点、文件被占用时的打包和解开没在电脑上实测。
- 第 4 轮：边框在多显示器、高 DPI 下的样子没有专门看过。
- 签名窗口的闪烁提醒：要碰上真实的签名或登录窗口才能实测。急停键和让路已经在电脑上实测，急停键按下没反应的问题在 0.10.2 修好（见 `issues/004-x-第4轮桌面.md`）。
- 以后再看：MCP tasks 扩展、本机 MCP 网关升级到 2026-07-28 并接入 Playwright、Windows ODR 与代理隔离、示教录制、服务和注册表专用工具、断线根因。

**关闭时要满足：** 四轮各自发版，并在用户电脑上实测；长等待的实测结论写进 notes。

**合并回 project spec 的候选：** 工具一览；等待模型（首字节、进度、转后台）；防休眠；文件进出电脑的方式；桌面的多路做法。已合并，见下一节。

## 关闭（2026-11-01，用户要求收尾）

**为什么可以关。**
- 四轮都实现了，都装到了用户电脑上，并且在电脑上实测过：001–004 每张票都有实测记录和关闭结论。
- 实测中发现了三个问题，都已修好并复测：
  - 经连接器的长等待会被切断，0.10.1 修；
  - 任务命令里写了 `exit`，退出码就丢了，0.10.1 修；
  - 急停键更新后按了没反应，0.10.2 修。
- 长等待的实测结论写进了 `.agents/notes/implemented/feature/2026-11-01-relayed-calls-wait-40s.md`。

**和关闭条件的一处偏差。** 条件写的是“四轮各自发版”，实际没有：0.7.4、0.8.0、0.9.0 只在分支上改了版本号。用户 11-01 要求按建议推进、直接用到电脑和服务端，四轮于是一起随 v0.10.0 发布，之后又发了两个修正版 v0.10.1、v0.10.2。“每轮都装到电脑上实测”这个目的达到了。

**合并到 Project Spec 的位置。**
- `codestable/spec/index.md`：项目是什么、一次典型使用、能力地图（即工具一览）、三个部分怎样连起来、统一语言、边界与考量（不改现有参数的含义、开场说明 4096 字符、结果约 4 万字节、中转只转发、不是沙箱、长期质量约束）。
- `codestable/spec/waiting.md`：等待模型（每次调用的上限、经中转为什么只给 40 秒、提前返回的几种情况、轮询只回新内容）、编号和退出码、防休眠、电脑不在线时。
- `codestable/spec/files.md`：文件工具守住的几件事、一次性链接（文件夹、解开、分片）、暂存目录、服务器。
- `codestable/spec/desktop.md`：桌面的多路做法、`ui` 的编号与批量、截图、程序授权、主人在电脑前时（让路、急停、边框）、操作不了的情况。
- 操作经验另记在 `codestable/notes/001-发版与部署.md`：发版、装到电脑上、部署中转的步骤和坑。
