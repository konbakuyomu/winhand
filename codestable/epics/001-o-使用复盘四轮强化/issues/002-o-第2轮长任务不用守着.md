# 第 2 轮（0.8.0）：长任务不用守着

## 做成以后是什么样

- **长等待。** `job_status`、`session_wait`、`mcp_call` 可以一直等到任务结束、匹配到 `patterns`，或者到上限，期间每 20 秒发一次进度，不用 AI 一轮轮地问。
  - 在 Claude Code 主对话里，超过 2 分钟的调用会转到后台，结束时叫醒 AI。
  - 其他客户端仍是 40 秒。
- **工具注解。**
  - 读类工具标 `readOnlyHint`：可以并行，断线时 Claude Code 会补发一次。
  - 常用工具标 `anthropic/alwaysLoad`。
  - 真正的失败标成错误。
- **防休眠。** 后台任务、`run`、会话运行期间，电脑不睡；结束后恢复。`config.toml` 可以关掉。
- **`job_start` 和 `job_status` 加强。**
  - `job_start` 加 `timeout_s`、`script=`；装了 PowerShell 7 时默认用它；用 Job Object 管整棵进程树。
  - `job_status` 多报：CPU、多久没有输出、是否卡住（`stalled`）、任务进程弹出的窗口，还能顺便看几个日志文件（`files=[…]`）。
- **中转。**
  - 提供 JSON 状态：是否在线、最后在线时间、版本。
  - 电脑离线较久时，调用立刻报错，不再每次等 20 秒。

## 为什么现在做

- `job_status` 占调用的 16.6%，0.7.0 之后累计等了 30.9 小时。
- 用户先是要求省钱少轮询（10-22），后来又因为发现晚了 1 小时，要求查得更勤（10-31）。
- 6 个对话被电脑睡眠打断；Freerouting 弹窗卡住任务，要用户手动点掉；一次卡住的任务被空轮询了 29 次。

见 `docs/reviews/2026-11-01-usage-review.md` 第四节 1、3、4。

## 风险与穿刺

1. **先穿刺：经中转和 claude.ai 连接器能不能长时间流式回复。**
   - 做法：加一个测试用的等待工具，每 20 秒发一次进度，等 5 分钟。
   - 打通的标准：不被截断；主对话里转后台，结束时有通知。
   - 要装新版，再在云端会话里试，需要用户配合。
   - 不通时的备选：在沙箱里用后台 curl 长轮询“等待链接”，命令结束即叫醒。
2. **只读注解和长等待同一版上线。** 否则 AI “一轮连发 3 个等待”会变成同时返回。
3. **防休眠由任务包装脚本自己持有**，winhand 重启不影响。

## 待定（用户）

- **防休眠默认值。** 暂定“运行期间不睡，可关”。是否只在接电源时这样，等用户确认。
