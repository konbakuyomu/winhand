# 使用复盘后的四轮强化

> **读者：** 接手这条改进线的人——相对 0.7.3 要改什么、现在怎么理解方案、哪些能推、哪些还悬着、关了合回哪里。

---

## 这条线要改变什么

依据 `docs/reviews/2026-11-01-usage-review.md`（09-26 至 11-01 的调用日志、10-19 至 10-31 的 66 个云端会话、Smart Search 调研），补上 AI 在 WinHand 上被迫绕路的地方。分四轮，每轮一个版本：

| 轮次 | 版本 | 要解决的事 |
|---|---|---|
| 第 1 轮 | 0.7.4 | 读文档丢正文的 bug；轮询回复瘦身；开场说明补 `remote_run`、`fs_send`、提交信息的写法；`run` 编号与几个小参数 |
| 第 2 轮 | 0.8.0 | 长任务不用守着：长等待加进度、工具注解、防休眠、后台任务加强、中转状态 |
| 第 3 轮 | 0.9.0 | 文件进出电脑和服务器：多文件与文件夹传输、大文件分片、暂存目录、一次处理多个目标的文件工具、`context` 简要模式、`remote_run` 补齐 |
| 第 4 轮 | 0.10.0 | 桌面：`input` 补全、`ui` 与 OCR 小改、控件 `ref` 与批量、主人在场、命令被弹窗卡住时提醒 |

关联 spec：`codestable/spec/index.md` 还是骨架。本 Epic 关闭时，把稳定下来的结论合并进去。

## 当前怎么理解（活规格）

- **不改现有参数的含义。** 新能力用新参数或新取值打开。Claude Code 以外的客户端保持旧行为，例如等待的 40 秒上限。
- **等待。** Claude Code 对 HTTP 和 claude.ai 连接器的单次请求只限首字节 60 秒；空闲 5 分钟，收到进度就重新计时；主对话里的调用超过 2 分钟自动转后台，结束时通知（`code.claude.com/docs/en/mcp`，2026-11-01 核对）。长等待的前提是一开始就发进度、之后每 20 秒发一次。经连接器的路径实测通过之前，长等待只在显式要求时打开。
- **只读标记与长等待同一版上线。** 标了 `readOnlyHint` 后，同一轮里的几个 `job_status` 会同时返回，AI 现在“一轮连发 3 个等 2 分钟”的做法就不灵了。
- **防休眠由任务自己持有。** 用 `SetThreadExecutionState`，任务结束即释放；winhand 重启不影响已经在跑的任务；`config.toml` 可以关掉。
- **WinHand 自己不做的事。** 发版、部署中转、改用户电脑上的守卫规则，都要用户在电脑上确认。

## 现在推什么、先搁什么

**Issues：**（都在同目录 `issues/` 下，编号只在本 Epic 内有效）

- [ ] `issues/001-o-第1轮小修.md` — 0.7.4；不依赖其他轮
- [ ] `issues/002-o-第2轮长任务不用守着.md` — 0.8.0；长等待的默认值要等连接器路径实测
- [ ] `issues/003-o-第3轮文件和服务器.md` — 0.9.0
- [ ] `issues/004-o-第4轮桌面.md` — 0.10.0；Windows 专属，靠 CI 的 Windows 任务和用户电脑验证

**暂不推进 / 未确认：**

- 长等待经 claude.ai 连接器的实测：要先装新版，再在云端会话里试。
- 防休眠的默认值：先定为“任务、命令、会话运行期间不睡，结束后恢复，可在 `config.toml` 关闭”，等用户确认。
- 暂存目录自动清理：默认不清理，等用户同意。
- 守卫规则补丁（rule 1 的几种绕过写法、`fs_op` 能删整个目录）：只出建议，用户确认后由用户改。
- 以后再看：MCP tasks 扩展、本机 MCP 网关升级到 2026-07-28 并接入 Playwright、Windows ODR 与代理隔离、示教录制、服务和注册表专用工具、断线根因。

**关闭时要满足：** 四轮各自发版，并在用户电脑上实测；长等待的实测结论写进 notes。

**合并回 project spec 的候选：** 工具一览；等待模型（首字节、进度、转后台）；防休眠；文件进出电脑的方式；桌面的多路做法。
