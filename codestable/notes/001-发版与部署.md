# 发版与部署

> **读者：** 要发一个新版本、部署中转，或者让主人的电脑装上新版的人。

---

**结论：** 发版只需推一个 `vX.Y.Z` 标签，版本号要和 `agent/pyproject.toml` 一致。云端沙箱推不了标签，要从主人电脑上的检出推。中转只有改了 `relay/` 才需要部署，在电脑上运行 `wrangler deploy`。新版要装到电脑上，得请主人在桌面端里点更新。

**何时用：** 改了 agent、桌面端或中转，要让主人的电脑和线上用上。

**细节：**

- **改版本号**：三处一起改。
  - `agent/pyproject.toml`
  - `agent/src/winhand/__init__.py`
  - `agent/uv.lock` 里 winhand 的那一条
- **先跑 CI**：`.github/workflows/` 里的 agent、desktop、relay 三个工作流只在推到 main 或开 PR 时自动跑；在分支上要用 workflow_dispatch 手动触发。
- **打标签**：`.github/workflows/release.yml` 由 `v*` 标签触发，大约 6 分钟。它先核对标签和项目版本号一致，再构建、签名、发布安装包和增量包。
  - 云端沙箱推标签时，git 代理会断开连接（“send-pack: unexpected disconnect”）。
  - 所以在主人电脑的检出里打：先 `git fetch` 那个分支，核对分支头就是 CI 通过的那个提交，再 `git tag -a vX.Y.Z <提交> -m vX.Y.Z`，然后推送标签。
- **装到电脑上**：AI 碰不到 WinHand 自己的窗口，所以要请主人在桌面端点「设置 → 检查更新 → 下载 → 重启」。之后中转的 `/status.json` 里 `version` 会变成新版本。
- **部署中转**（只在改了 `relay/` 时）：
  - 先用 `git log -- relay/` 找出最后一次改中转的提交。比上次部署的代码新，才需要部署。
  - 在电脑上用一个 worktree 检出要部署的提交。从主检出把不进仓的 relay/wrangler.deploy.jsonc 拷过去，运行 `npm ci`，再运行 `npx wrangler deploy --config wrangler.deploy.jsonc`。
  - 2026-11-01 那次，更新路由的一步报 “Could not find zone”，原因是 OAuth 登录缺域名权限。代码其实已经传上去了，原来的自定义域名也照常指向它。以后要改路由或域名，先运行 `npx wrangler login` 重新授权。
  - 核对是否部署成功：`npx wrangler deployments list` 看最新一次部署的时间和版本；`/status.json` 里的字段要和新代码对得上。
