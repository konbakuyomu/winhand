# 发版与部署

> **读者：** 要发一个新版本、部署中转，或者让主人的电脑装上新版的人。

---

**结论：** 发版只需推一个 `vX.Y.Z` 标签，版本号要和 `agent/pyproject.toml` 一致。云端沙箱推不了标签，要从主人电脑上的检出推。中转只有改了 `relay/` 才需要部署，在电脑上运行 `wrangler deploy`。新版要装到电脑上，得请主人在桌面端里点更新。

**何时用：** 改了 agent、桌面端或中转，要让主人的电脑和线上用上。

**细节：**

- **改版本号**：三处一起改。
  - `agent/pyproject.toml`
  - `agent/src/winhand/__init__.py`
  - `agent/uv.lock` 里 winhand 的那一条
  - 只改版本号的提交也会过提交前的结构检查（`agent/src/winhand/__init__.py` 在受管目录里）：同一次提交要带一条知识改动，例如在票里写一句「随 X.Y.Z 发出」。
- **先跑 CI**：`.github/workflows/` 里的 agent、desktop、relay 三个工作流只在推到 main 或开 PR 时自动跑；在分支上要用 workflow_dispatch 手动触发。
- **合并 PR**：用 squash。合并后同名的开发分支接着用：先 `git merge origin/main`（内容相同，只是接上历史），再普通推送；强推会被拦下。
- **打标签**：`.github/workflows/release.yml` 由 `v*` 标签触发，大约 6 分钟。它先核对标签和项目版本号一致，再构建、签名、发布安装包和增量包。
  - 云端沙箱推标签时，git 代理会断开连接（“send-pack: unexpected disconnect”）。
  - 所以在主人电脑的检出里打：先 `git fetch` 那个分支，核对分支头就是 CI 通过的那个提交，再 `git tag -a vX.Y.Z <提交> -m vX.Y.Z`，然后推送标签。
  - 发布说明取自上一个标签以来的提交标题（不含合并提交），以 `chore`、`ci`、`docs`、`test` 开头的会被滤掉，全滤掉就写成「维护更新」。squash 合并时提交标题就是 PR 标题，所以发版的 PR 标题要以 `fix:` 或 `feat:` 开头。
  - 盯发布流程不用自己轮询：在电脑上用 `job_start`（`secrets=['GH_TOKEN']`）跑一个循环，反复运行 `gh run list --workflow release.yml`，等那次运行结束，再用 `gh release view vX.Y.Z --json assets` 列出发布物；把它的 wake 链接在云端后台运行，任务一结束就叫醒会话。核对时把发布物里的 SHA256SUMS.txt 和 GitHub 记录的每个发布物的 sha256 对一遍。0.15.1 就是这样做的，约 6 分钟。
- **装到电脑上**：AI 碰不到 WinHand 自己的窗口，所以要请主人在桌面端点「设置 → 检查更新 → 下载 → 重启」。之后中转的 `/status.json` 里 `version` 会变成新版本；云端会话可以在后台循环读 `/pc/<名称>/status.json`，等 `version` 变成新版本再复测。
- **部署中转（自托管，生产在 LAX）**：只在改了 `relay/` 并合并到 main 以后做。在 LAX 上以 root 运行：

  ```bash
  curl -fsSL https://raw.githubusercontent.com/konbakuyomu/winhand/main/relay/selfhost/install.sh | bash -s -- winhand-lax.konbakuyomu.us --cimd on
  ```

  - 它先构建再换容器，中转只停顿几秒；之后检查首页，和原来在线的电脑重新连上，不健康就自动回退（见 `relay/selfhost/README.md`）。
  - `--cimd on` 必须带：LAX 上的 claude.ai 登录是 CIMD 客户端，关掉 CIMD，这些登录刷新会失败。
  - 2026-11-25 起 LAX 不再设 `AGENT_TOKEN`：`default` 已移除，只剩 `/pc/<名称>/` 的地址。`secrets/` 里没有 `agent-token`，`relay/selfhost/install.sh` 也不会再把它加回来。
  - 从云端会话做时，经 winhand 的调用本身就走这个中转，换容器时会断。所以要在 LAX 上后台跑，例如 `setsid nohup bash -c '<上面的命令>' > /root/winhand-upgrade.log 2>&1 &`。命令发出后，等几分钟不调用电脑，再看日志和 `/status.json`。
- **部署中转（Cloudflare Worker，旧域名，留作回退）**（只在改了 `relay/` 时）：
  - 先用 `git log -- relay/` 找出最后一次改中转的提交。比上次部署的代码新，才需要部署。
  - 在电脑上用一个 worktree 检出要部署的提交。从主检出把不进仓的 relay/wrangler.deploy.jsonc 拷过去，运行 `npm ci`，再运行 `npx wrangler deploy --config wrangler.deploy.jsonc`。
  - 2026-11-01 那次，更新路由的一步报 “Could not find zone”，原因是 OAuth 登录缺域名权限。代码其实已经传上去了，原来的自定义域名也照常指向它。以后要改路由或域名，先运行 `npx wrangler login` 重新授权。
  - 核对是否部署成功：`npx wrangler deployments list` 看最新一次部署的时间和版本；`/status.json` 里的字段要和新代码对得上。
