# 桌面

> **读者：** 要改桌面工具的人：AI 怎样操作没有命令行的程序，什么时候必须停下来等人，哪些情况根本操作不了。

---

## 操作一个程序，按这个顺序选路

一条走不通再换下一条，从最稳的开始：

1. **程序自己的命令行、接口或文件**，例如 KiCad 的 kicad-cli。
2. **`ui` 按名字操作控件。** 用 Windows 的 UI Automation，经典 Win32 程序的菜单、树、列表、工具栏也读得到。原生接口用不了时退回 PowerShell 脚本，结果里的 `backend` 写明用的是哪个。
3. **快捷键**：`input(action="keys")`。
4. **`ocr` 认屏幕上的字**：用于没有控件的界面，比如画布、远程桌面、自绘界面。用 Windows 自带的 OCR，可以按文字点击，也可以等文字出现或消失。
5. **按坐标点击**：最后才用，每次点完都截图核对。

越靠前的路，越不受窗口大小、主题和 DPI 的影响；出了错，也越说得清是哪一步错了。

## `ui`：按编号操作，一次做几步

- **编号。**
  - 每次 inspect 把控件按顺序编号为 `e1`、`e2`……，之后用 `ref='e12'` 操作这一个控件。编号用到下一次 inspect 为止，最多记 8 个窗口的。
  - 按编号操作时，重新读这个控件本身。找不回同一个控件就报“窗口变了，重新 inspect”，不会点到别的控件上。
- **一次做几步。** `steps=[…]` 按顺序做 `ui` 动作和 `keys`、`type`、`wait`；出错、等不到或回读对不上就停下，最后截一张图。填表、勾选、点按钮，一次调用就能做完。
- **回读核对。**
  - 每个动作只做一次，之后回读控件状态：`verified` 是 true、false，或 null（无法确认）。
  - 点了按钮，不等于它触发的工作已经做完，要再看结果窗口。
  - 动作打开的新窗口（确认框、报错、文件选择框）列在 `new_windows` 里。
- **找控件。** `filter='文件名|打开'` 匹配其中任一段文字，也匹配控件的类名。窗口在读的过程中变了，会自动重读。

## 截图

- **大小。** 长边不超过 1568 像素，总共约 115 万像素以内。这是 Claude 不会再自行缩小的上限，所以按截图上的像素点击才不会偏。原尺寸的图存在电脑上（`original_file`），要看细节就用 `fs_read` 加 `region` 放大。
- **等画面，不要睡。**
  - `screenshot(wait="change")` 等画面有变化，`wait="stable"` 等画面停止变化。
  - 没给窗口时，只看最前面的那个窗口，别处在放视频也不影响。
  - 等不到时，`kept_changing` 写明一直在变的区域。
- **最小化的窗口直接截。**
  - 先不抢焦点地把窗口显示出来，截完按原来的摆放放回去；原来是最大化的，还原后仍是最大化。
  - 这算读：焦点不动，状态原样放回，所以不弹授权。代价是窗口会在屏幕上闪现约半秒。
  - 复盘时，截最小化窗口失败过 11 次，而先把窗口还原又要授权。

## 程序授权

AI 第一次点击、输入或操作某个程序时，电脑上弹窗问主人，有三个选择：
- 拒绝（默认焦点）；
- 允许到 WinHand 重启；
- 一直允许，记在 `~/.winhand/desktop-apps.toml`。

截图、读字、inspect 不需要授权。终端窗口一律拒绝，让 AI 改用 `run` 或会话，那里有守卫把关。WinHand 自己的窗口（授权弹窗、守卫确认框、桌面端），任何桌面工具都碰不到。

## 主人在电脑前时

有三层保护，都可以在 `~/.winhand/config.toml` 的 `[desktop]` 里分别关掉。`sys_info()` 的 `desktop_owner` 显示当前设置，以及急停键注册上了没有。

- **让路。**
  - 主人最近 5 秒内动过鼠标或键盘时，AI 的桌面动作（`input`、`ui` 的动作、`ocr` 的点击、`window` 的操作）先等主人停手，最多等 10 秒。
  - 主人还在用，就报“这人正在用电脑”，什么也不做。
  - WinHand 自己发出的输入、主人在 WinHand 弹窗里的操作都不算。嵌套的动作只在最外层等一次。
- **急停。**
  - 按 Ctrl+Alt+Shift+Backspace 以后 60 秒内，桌面动作一律拒绝，回复说明是主人按的；`steps` 做到一半时，从下一步起停下。
  - 急停键在 WinHand 一启动就注册。热键同一时间只能归一个进程，所以按下的时间写进 `~/.winhand/desktop-stopped`：电脑上的每个 WinHand 进程（桌面端的、本机 stdio 的）都读这个文件，一起停。没抢到热键的进程，每次桌面动作时再试着注册一次。
  - 一次急停最多 60 秒，系统时钟被改过也一样。
  - 对话里没法提前恢复。“按两次就恢复”的做法被否掉了：手忙脚乱时按了两次，会在主人以为已经停下时又放开。
- **边框。** AI 操作桌面时，屏幕四周有一圈橙色细框，最后一个动作之后 2 秒消失。它不出现在截图里；系统做不到这一点时（Windows 10 2004 以前），干脆不显示。

**怎样判断“人在用电脑”。**
- 读系统记下的最近一次输入时间。WinHand 每次自己发输入都记下时刻，之后 500 毫秒内看到的输入算 WinHand 自己的。
- 这个办法分不清输入是谁发的：别的远程控制程序发来的输入，也算人在用。
- 没有用全局低级钩子来区分。钩子要在每次鼠标移动时跑一遍 Python 回调，回调一慢，整台电脑的输入都会跟着卡。

## 操作不了的情况

- **锁屏、UAC 提示、远程桌面会话断开时**：输入和点击直接说明原因，不发送；整屏截图和读字也直接说明原因，不返回黑图。
- **以管理员身份运行的程序**：Windows 会悄悄丢掉普通程序发给它的点击和按键。
  - 窗口列表里，这类窗口标 `admin: true`；
  - `ui`、`input`、`ocr` 的点击会拒绝，并说明原因；
  - 截图和读字照常。
