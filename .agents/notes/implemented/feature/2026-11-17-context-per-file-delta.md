# Agent Note: context 的 since 按文件给增量，超长文件给目录加结尾

Status: implemented

## Problem

2026-11-17 的使用复盘（`docs/reviews/2026-11-17-usage-review.md` 第四节第 3 条）量到：

- 11-02 至 11-17 共调 `context()` 759 次，544 次指向 rk3588-core-board 和它的暂存目录，只有 46 次带 `since`。
- rk3588 的 brief 结果从 11-05 的 22,618 字涨到 11-16 的 41,527 字，碰到单次结果上限。项目 CLAUDE.md 709 行只给到 577 行。
- 截断按顺序保留每个文件的开头，主人新加的授权都追加在文件末尾，所以被截掉的总是最新的那几段。
- `since` 对整份回答取指纹，任何一个文件改一个字，整份重发；rk3588 的 CLAUDE.md 几乎天天追加，带 `since` 的调用照样回 4 万多字。
- 子会话压缩一次就重读一遍：旧总调度 11-12 在 63 分钟里压缩 4 次，每次重读约 2.8 万字的 context。

不改的话，规矩越写越长，AI 越来越看不到最新的授权，每个会话花在重读规矩上的额度也越来越多。

## Decision

- `workspace.context(cfg, path, repo, since)` 给每个规则文件算指纹（`sha`，全文 sha256 的前 16 位），并把没截断的全文记在 `_context_cache`（按 digest 记最近 64 份，在内存里）。
- digest 按没截断、已脱敏的全文算，所以同样的规矩总是同一个 digest。
- 带 `since` 时：
  - 和现在的 digest 相同：照旧只回 `unchanged`；
  - 能在缓存里找到那一份：没变的文件只给 `path`、`format`、`scope`、`lines`、`sha` 和 `unchanged: true`；新内容以旧内容开头的文件（只在末尾追加），给 `appended_after_line` 和新加的部分；其余文件给全文；
  - 找不到（winhand 重启过，或已被挤出 64 份）：给全文。
- 超过预算的文件给 `Headings:` 目录（`#` 开头的行，带行号，最多 60 条）加文件最后几行；`truncated` 写明给了第几到第几行，并给出读前面部分的那条 `fs_read(path, offset=1, limit=…)`。

## Alternatives considered

- **只把 rk3588 CLAUDE.md 的授权一节挪到单独文件。** 最强的理由：一个文件改一下，立刻少一半字数。没有只做这一条：它只救这一个仓，别的仓的规矩照样会长，截断截后面的问题还在。主人在复盘第七节第 4 条也选了挪，两件事一起做。
- **截断改成只保留结尾。** 最强的理由：最新的授权一定在。否掉的原因：文件开头往往是总纲（读者、目录、硬规矩），只留结尾会丢掉这些；目录加结尾两头都顾到，剩下的写明去哪读。
- **每次只给指纹，让 AI 按需 `fs_read`。** 最强的理由：字数最少。否掉的原因：第一次读必须有全文，规矩是要照做的，不能指望 AI 自己去翻；增量只在已经读过的会话里用。
- **把缓存写到磁盘，重启后也认得。** 最强的理由：winhand 更新以后，`since` 还能省。没这样做：缓存的是规矩全文，落盘就多一份主人规矩的副本要管；winhand 重启不常见，重启后给一次全文的代价可以接受。

## Consequences

- **收益**：
  - 规矩没变的会话只收到几十字节；追加了授权的，只收到新加的几行；
  - 超长文件不再悄悄丢掉最新的部分，截了什么、去哪读写在回复里。
- **代价与已知上限**：
  - 缓存只在内存里：winhand 重启或更新以后，第一次调用给全文；
  - 不是末尾追加的修改（中间改一句），那个文件照样给全文；
  - 目录只认 Markdown 的 `#` 标题；别的格式的长文件只有结尾。
  - 发版一周后用 `docs/reviews/tools/activity_stats.py` 量每个子会话收到的规矩字节数。降不到一半，就重看这里，例如把缓存落盘，或者对中间修改也给差异。

## Verification

- 代码：`agent/src/winhand/workspace.py` 的 `context()`；`agent/src/winhand/server.py` 的 `context` 工具用 `full["digest"]`。
