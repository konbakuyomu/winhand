# Agent Note: 桌面端界面改版：按领域拆侧栏，Fluent 原生加长春花蓝

Status: implemented

## Problem

主人 2026-11-25 凌晨说，winhand 桌面端「太丑了」，而且布局不合理：设置里中转、密钥、程序授权全混在一起，应该有序放到侧边栏；会话页从来没用过。

0.14.0 的实情（主人电脑上的截图 `~/.winhand/scratch/ui-review/before-*.png`）：
- **设置页七块堆在一页**：中转、密钥、程序授权、启动、更新、本机数据、关于，滚四屏才到底。「添加密钥」「加入一直允许」都在列表的最底下。
- **窄窗口塌陷**：主人日常窗口约 853×1018 逻辑像素。活动和 MCP 服务两页的左右分栏阈值高于内容区宽度，塌成上下两截：MCP 的服务列表被切掉一半，活动页下面 60% 空着，却写着「在左边选择」。
- **会话页**：长期是空的，却占着一个顶级导航项。
- **视觉**：
  - 黑色系统标题栏配纯白画布，强调色跟着系统走成了炭灰色；
  - 密钥每行四个带框按钮，十五行就是六十个按钮，删除和复制长得一样；
  - 看板娘被裁掉底座，旁边飘着一个状态小绿点。

Gemini 按 impeccable 的 critique 给现状打了 22/40。失败条件：主人在日常窗口里找不到、看不清，或者误点删除。


## Decision

从 0.15.0 起，桌面端是这样的。方案由 Claude 和 Gemini（agy-neon）在 parley t36 讨论两轮定下，视觉和布局以 Gemini 为准；GPT（Codex）按票执行，Claude 审查。细节在 `desktop/DESIGN.md`（视觉规范）和 `codestable/epics/005-o-桌面端界面改版/PAGES.md`（逐页规范和截图验收要点）。

- **信息架构**：
  - 侧栏主区：概览、活动、MCP 服务。会话平时不出现，有没退出的会话时才显示在活动下面，带计数；有会话等人处理（needs_user、blocked）时，计数变成琥珀色。
  - 「安全与连接」一组：密钥、程序授权、中转，各自成页。页脚是设置，只有启动与托盘、软件更新、本机数据、关于，一屏放下。
  - 侧栏可以折叠到 48 像素（Ctrl+B）。折叠后看板娘隐藏，只留状态圆点；折叠状态不跨重启保存。
- **视觉**：
  - 85% Windows 11 原生 Fluent，15% 品牌签名：长春花蓝强调色（浅色 #4F63D2，深色 #8EA0F8）；Mica 背景和一体化标题栏；88×88 的看板娘，旁边是全应用唯一的连接状态锚点。
  - 卡片只用 1 像素描边，不加阴影，不嵌套；图标只用 Segoe Fluent Icons；等宽字体只给工具名、路径、密钥名这类数据。活动标题全是 ASCII 时用等宽，有中文时用界面字体。
  - 颜色只在 `desktop/windows/App.xaml`：主题字典定义颜色，样式用 `{ThemeResource}` 引用，代码只设样式。主人切换深浅色时，颜色跟着变。坑和做法见 `codestable/notes/002-桌面端的主题画刷.md`。
- **各页**：
  - 概览：一张状态卡，上半是连接状态和随状态变化的按钮，下半是今日调用、MCP 服务、活动会话三格，整格可点。只在有新版本时多一条提示，不再重复显示连接状态。最近 8 条活动可点，点了跳到活动页并选中这一条。
  - 活动：两行工具栏，「失败」筛选不会被挤掉。内容区宽于 760 时左右分栏；窄时选中一条才从底部弹出详情抽屉，Esc 关闭。
  - MCP 服务、会话：分栏阈值 568。再窄时先显示列表，点进详情，上方有返回。
  - 密钥：每行只有「显示」「复制」两个轻按钮，修改和删除在「⋯」菜单里。显示时顶部有防截屏横幅和 30 秒进度；复制后按钮变成「已复制」。
  - 程序授权：总开关和「提前加入一直允许」在最上面。撤销一直允许立即生效，右下角给 8 秒「恢复」，指针移入时暂停；撤销临时授权不给恢复。
  - 操作反馈：右下角浮动的实底提示条。成功和信息几秒后收起，警告和错误要手动关。
- **不变量没变**：
  - 密钥显示 30 秒，显示期间窗口不进截图（WDA_EXCLUDEFROMCAPTURE），离开密钥页、隐藏窗口、后端断开时立即隐藏；
  - 复制不进剪贴板历史、不跨设备同步；令牌不回显；
  - 后端协议不改。
- **验收工具**：`desktop/scripts/Capture-Preview.ps1` 用假后端 `desktop/scripts/preview_backend.py` 按页截图。`-Theme` 在应用级设深浅色，`-State` 截页面状态（显示中的密钥、选中的活动、折叠的侧栏等）。

## Alternatives considered

- **引入 CommunityToolkit 的 SettingsCard。** Gemini 第一轮推荐。
  - 最强的理由：现成的 Windows 11 设置行，悬停、焦点、无障碍都齐，GPT 手写行容易对不齐。
  - 否掉的原因：项目用 Windows App SDK 2.5.1，Toolkit 8.x 按 1.x 构建，自包含发布有兼容风险；需要的行样式只有三四种，收进 `MainWindow.Layout.cs` 的辅助方法一样能防走样。改用零依赖样式（PAGES.md 第 5 节）。
- **重品牌皮肤，或者暗色极客仪表盘。**
  - 最强的理由：辨识度高，和别的工具一眼区分开。
  - 否掉的原因：winhand 管着密钥和桌面操作权限，属于 impeccable 说的 Operate 界面，可信要靠熟悉的原生秩序；非标控件、霓虹装饰只会显得像套壳。
- **百分之百系统默认的 WinUI。**
  - 最强的理由：零设计成本，永远和系统一致。
  - 否掉的原因：现状基本就是这样，炭灰强调色加纯白画布，主人的原话就是「太丑」。
- **会话页并进活动页。**
  - 最强的理由：少一个导航项，会话本来也是活动的一种。
  - 否掉的原因：会话要能停止、看日志，是可操作的对象，并进时间线会混。改成平时隐藏、有会话才出现，功能全保留。
- **悬浮提示条放右上角。** Gemini 第一轮的位置。
  - 否掉的原因：打开时会盖住页首的主操作（添加密钥、授权文件、编辑）。改到右下角。
- **代码里取画刷，或者用 `XamlReader.Load` 解析带 `{ThemeResource}` 的片段。** 第 3、4 张票的 GPT 各用了一种。
  - 最强的理由：不用改共享的 App.xaml，两张票能并行。
  - 否掉的原因：前一种不跟着主人切换深浅色；后一种字符串散在各处，活动列表每行还要解析两次。合并后统一改成 App.xaml 里的样式。

## Consequences

- **收益**：
  - 设置从四屏变成四个落点；
  - 853×1018 的日常窗口里，MCP 服务和会话直接左右分栏；活动页不再有大片空白；
  - 密钥和授权行不再是按钮墙，删除进了菜单；深色模式可用。
- **代价**：
  - 显示中的密钥截不到图（窗口不进截图），这一态只能用眼睛验收。
  - 预览里手点一遍要主人来做：AI 不能操作 WinHand 自己的窗口。
  - 留到以后的小事：拖动条的鼠标形状、WinHand 的大小写统一、活动行里参数被截断时的箭头尾巴、密钥显示态的几处微调。
- **回退**：界面改动都在 `desktop/windows/` 里，协议没变，可以整体回到 0.14.0 的界面。

- 主人电脑上用预览底座按 853×1018 截图：浅色、深色各 8 页；加上抽屉、折叠侧栏后的分栏、MCP 出错、撤销后的恢复提示、700 宽时只剩列表、空数据，截图期间预览没有抢前台。
- Gemini 对照 `PAGES.md` 第 6 节验收两轮：第一轮（parley t36 m333）提出六处，改完复验通过。
