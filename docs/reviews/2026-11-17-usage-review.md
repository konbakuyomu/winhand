# WinHand 第二次使用复盘与下一轮建议（2026-11-17）

状态：已按建议立 Epic 002（`codestable/epics/002-o-第二次复盘五轮强化/`）。这次只做调查和方案，没有改 winhand 的代码；只给复盘脚本补了四项统计（`codestable/issues/003-x-ff-复盘统计脚本补四项.md`）。第七节的四件事要你定，其余照你的「全自动推进」规则由我取推荐项。

## 一、结论

这半个月 winhand 的调用本身很稳：54,259 次，报错 0.5%。变的是用法：
- 两任 RK3588 总调度全天候派出 258 个子会话；
- 笔记本一天离线三四个小时；
- 你的 Claude 额度成了硬约束：11-07 17:4x 用完，各线停了约四天。

浪费主要不在调用失败，而在**等待和重复读**。按代价排：

1. **还是靠闹钟醒，不是任务一完就醒。**
   - 子会话每 ≤10 分钟用 `send_later` 醒一次，另有看门狗会话巡检。11-07 时最近 100 个会话里 24 个是看门狗。
   - 每醒一次，都要把 30–60 万 token 的上下文重读一遍。一个考官会话 11.5 小时花了 44.5 美元、1.56 亿缓存读。
   - 唤醒还常晚到：定时回访晚 2.5–20 分钟，有作业跑完 33 分钟没人取。
   - 电脑往会话推消息试过两次：`claude -p --cloud` 要在电脑上登录，你不愿意；GitHub 信箱叫醒只要 14 秒，但会话要挂上那个仓，开 PR 和评论也要你本人点头，所以票上都带 `--no-inbox`。
   - 中转的 `/hook/` 是现成的第三条路：沙箱代理已经放行它并自动带令牌，后台命令一结束就会叫醒 AI，等待期间零回合。
2. **规矩太大，还截掉了最新的授权。**
   - `context(brief, path=rk3588-core-board)` 一次约 4 万字节，到了单次上限；CLAUDE.md 709 行只给到 577 行，截掉的正是最近几天追加的授权。
   - 13 天带这个路径调了 544 次，每次压缩后都要重读。`since` 实际省不下来：任何一个文件变了，就整份重发。
3. **多会话共用一台电脑，彼此的输出互相灌进上下文。**
   - `job_status()` 不带 id 时，回 1.3–3 万字的别人的任务；`job_stop` 一次回了 2.3 万字。
   - `run-N` 只保留最近 20 条，几个会话一起跑就会被挤掉，丢过退出码。
   - 排队程序本身是个 winhand 任务，电脑重启或睡眠后就没了，靠每 10 分钟一次的巡检拉起（6 天 717 次）。
4. **两处确认的 bug，都让 AI 改用脚本绕路。**
   - `fs_write(append)` 不跟随文件的换行。CRLF 文件里混进 LF 行之后，`fs_edit` 报「100% 相同」，差异却是空的。AI 于是改用 Python 或 PowerShell 重写文件：总调度 3 小时里 22 次，W/Q 线 23 次。
   - 守卫有 3 次误伤：搜索的模式串里有 `rm`、`rmtree`，Python 里有个变量叫 `ri`，都被当成批量删除拦下。
5. **暂存目录 22 GB、37 万个文件，里面混着要紧的东西**：封存的考题名单、指向工作区的联接点、Colab 的 Google 登录。11-01 定「不清理」时它只有 41 MB。

建议分五轮，见第六节；要你定的四件事在第七节。

## 四、问题细节和证据

### 1. 叫醒：靠闹钟，晚，而且贵

**怎么等的。**
- 子会话等的多半是你的单道 `board queue`，它本身是 `job_start(command='board queue run', name='board-queue')` 起的 winhand 任务。少数等 Codex 和 Colab。
- 等法是按排队的估时设 `send_later`；作业在跑时，最多 10 分钟醒一次。这条是 11-01 你那句「23点20分就跑完了……到了第二天 0点22分才等待结束，浪费了一个小时」以后写进 rk3588 CLAUDE.md 的。
- 每次醒来都是一样的几步：读通知，常常先用 ToolSearch 重新加载 winhand 工具，`board queue status | Select-String`，再设下一个闹钟。
  - H5：2.8 小时醒 16 次（`…3ewrPPjxZp`，11-14 17:34–20:25Z）；
  - N17：4.5 小时 25 次 `send_later`、56 次 `run`（`…cpKi9y6p9s`）。
- 新总调度 11-17 09:22–09:31Z 发了 14 次 `job_status`，10 次等满 30–40 秒都没有新东西；同一段读了 16 次通知，13 次是空的。

**晚多少。**
- 调用日志：822 个被问到结束的任务，看到「已结束」比实际晚的上界是中位 0.4 分钟、p75 9.0 分钟、p90 15.7 分钟，累计上界 141.7 小时。
- 定时回访晚到：有两头时刻可比的 5 次里，4 次晚 2.5–3.3 分钟，1 次晚 19.6 分钟（最晚那次：`…ioyAwsoRqn`，11-13 12:53Z 到期、13:12:35Z 才触发）。
- 看门狗催取：「已在 00:59 跑完（过了 33 分钟没人取）」（`…FCKcQL4syJ` 17:32Z）；「作业 A13-t132 03:28:40 跑完了，A13 还没取」（`…LSVCwqBCqW`）。
- 一次 Codex 审查一启动就失败（不在受信目录），24 分钟后的回访才发现（`…ioyAwsoRqn` 07:28→07:53Z）。
- 想长等的被截成 40 秒：调用日志里 83 次（600 秒 35 次、1800 秒 29 次）。

**贵在哪。** 醒一次的代价约等于重读一遍上下文。
- 考官 Q3 每 8–20 分钟醒一次，11.5 小时 44.5 美元、1.56 亿缓存读（`session_0129got8f6HSv9Yhb9SqVhuP`）。
- N3 200 美元、C 162 美元，各约 5.2 亿缓存读。
- 旧总调度累计 2,448.75 美元；新总调度 5.2 天 1,339.81 美元。
- 11-07 你说「因为目前claude的总额度用了87%了，再这么推进下去很快烧完了」（`session_0129got8ApvNELeWeDPrpJVt` 03:05:32Z），当天 17:4x（本地）用完，停到 11-11 15:1x。
- 那个会话算过：G3 守着排队 31.6 小时（71.8 单位），E6 38 小时（62.8 单位），「最贵的不是干活的，是……等待」。
- 11-17 你说：「我在对话里已经多次询问模型的进度了，但这样效率很低，我对整体推进也没有清晰的概念。」（`session_0129got84ha6VzYRRR5vFjx6` 08:24:54Z）

**已经试过的推送。**

| 路 | 结果 | 出处 |
|---|---|---|
| 电脑 `claude -p … --cloud <会话>` | 1.3 秒失败：电脑上的 Claude Code 没登录 claude.ai；你定「我还是想就在云端使用」 | `session_0129got9XJknjNsWgLHyY5oW` 11-01 18:48Z、23:57Z |
| GitHub 信箱（dispatch-inbox，一票一个 PR，作业结束发评论） | 实测 14 秒叫醒，作业结束到发评论 1 秒。但会话要挂上那个仓（`add_repo` 被拦过，新总调度订阅不上 PR 6）；后订阅的会话会悄悄顶掉先订阅的；票上开 PR、评论要你本人点头，所以 38 张票全带 `--no-inbox`，只有巡检的 PR 6 在用，靠旧总调度转发 | `session_0129got8ApvNELeWeDPrpJVt` 11-07 03:44–04:42Z；旧总调度 11-13T11:28Z |

信箱那次的设计里，备选已经写着「winhand 的中转加一条通道，今天不做」。

**还能用什么**（文档 11-17 核对）：
- routine 的 `/fire`：每次新开一个会话，不能叫醒正在跑的那个。
- MCP tasks：只在 CLI 公测。
- 连接器的 60 秒：文档没写，是 11-01 实测出来的。
- 会话里的后台命令：结束时会把 AI 叫醒（本环境 Bash 工具说明原文：「re-invokes you when it exits」），云端最长 2 小时。
- 中转已经有 `/hook/<事件>`：单独的令牌头鉴权，只开这些路径，转发给电脑（`relay/src/hook.ts`）。沙箱代理已放行 `/hook/` 并自动带上令牌。

所以「电脑上的条件满足时，沙箱里的后台命令返回」这条路不需要登录电脑，不需要 GitHub 仓，也不需要新密钥。

### 2. 电脑离线、重启、睡眠

- 16 天离线 349 段，合计 54.1 小时，20 分钟以上的 17 段（附表）。离线期间一次调用都没有。winhand 的重连退避上限 30 秒，不是它等太久。
- 规律：早上约 07:00–08:50、傍晚约 17:50–19:30（本地）反复离线 85–105 分钟；另有几夜 7–12 小时。
- **计划内的停机处理得好。** 你先说暂停点，例如「跑到早上的8点05分暂停操作，电脑要暂时下线」「最后给你20分钟时间，准备暂停」。各线停在检查点，提交并写好「回来从哪接」，撤掉闹钟，回复「已暂停」。11-17 从你说到全部停好用了 13 分钟；回来后 9 分钟全部接上。
- **但回来以后要等你说一句。** 照规矩，只认你本人说「电脑回来了」。
  - 11-06 电脑 04:30Z 就回来了，各线等到 09:57Z 你说「恢复了，继续」才动，每个会话空等约 5.5 小时。
  - 11-17 电脑 11:24:53 重启回来，你 11:28:15 说「电脑回来了，继续推进」，这次只差 3 分钟。
- **排队程序活不过重启和睡眠。**
  - `board-queue-1102094250` 显示 vanished；11-13 17:49 睡眠时 3 个作业被打断（一个 rc 1073807364，两个没开始）。
  - 靠计划任务每 10 分钟巡检拉起：6 天跑了 717 次，看到它重开排队程序 3 次（11-12、11-13、11-14）。
  - 一个子会话也自己重开过它。
- **计划外的断线最伤。**
  - 11-12 05:44–05:57Z，旧总调度连续 8 次「timed out after 60s」（fs_read、history、sys_info、run），没有收到指向 `/status.json` 的快速报错。
  - 之后 winhand 工具从会话里消失，你说「已经连上了，继续」也没用，只好交接给新总调度（`session_01HfZLfLGU1dTxUr3nRVnXdo` 05:44–06:25Z）。
  - 11-13 又有一次连接器自己出故障，要重新授权；你换了连接器（WinHand LAX），旧会话里的工具就没了（`…ioyAwsoRqn`）。
- 断线原因：「no close frame」304 次、keepalive 超时 44 次、DNS 失败 3 次。11-14 起每天只有 4–5 次。

### 4. 多会话共用一台电脑

- **别人的输出灌进来。**
  - `job_status()` 不带 id 时，回 12,724 字、30,073 字的任务列表，全是别的票的；带了 `files=` 也被忽略（`…FCKcQL4syJ` 18:03Z、`…7sggSP1jA4` 20:42Z）。列表只取最新的 20 个，不分会话（`jobs.py` 448 行）。
  - `job_stop` 一次回了 22,672 字的输出（新总调度 09:31:38Z）。
  - Codex 的 stderr 长到 127–310 KB，`tail=100` 也有 6.7 KB 的差异文本，AI 只好约定「别用 job_status 读大输出」。
- **丢结果。** `run` 转后台的 `run-8211`，在 `job_status` 等待期间跑完，回的却是「no running command 'run-8211' (winhand keeps the last 20 after they finish)」，退出码丢了（`…5Z3MwaXg1P` 11-05 20:41Z）。调用日志里同类报错 6 次。`proc.py` 493 行：完成的命令只留最近 20 条，所有会话共用。
- **任务号跟着排队变。** 排队重排会给作业改名，A8 6 小时被改名约 11 次，每次都要花一个回合去追。会话最后改成按负责人和票号去认（这是排队程序的事，不是 winhand 的）。
- **交接后找前任的任务**：直接读 `~/.winhand/jobs/<id>/job.json`、`output.log`；压缩以后去翻自己的对话记录，`history()` 0 次。
- **电脑是瓶颈。**
  - 「前面 71 项、估时合计约 777 min（单道）」；B10 排在 75 位里的第 75，「约 19 小时」；
  - 两个布线作业并行时可用内存降到 4 GB，结果都跟着变了；
  - 总调度自己的话：「真瓶颈是电脑的排队（一条道）」。
- **git 撞车**：两个会话同时提交，`index.lock` 冲突；12 次提交先查锁，其中 5 次用 `Start-Sleep 3` 循环等。

### 5. 换行的一对 bug

- **`fs_write(append=True)` 原样追加字节**（`fs.py` 262–268 行），不看文件原来是 CRLF 还是 LF。CRLF 文件追加一段 LF 内容，文件就变成两种换行混着。
- **`fs_edit` 的换行处理是全有或全无**（`fs.py` 317–319 行）：文件里只要有 CRLF，就把 old 里所有 `\n` 换成 `\r\n`，于是混合文件里 LF 结尾的那几行永远对不上。
- 提示里比较前先统一了换行（`_closest`），所以显示「100% alike」，差异却是空的。看到过 4 次：`…CscDEnKbDX` 05:02Z、`…cpKi9y6p9s` 17:19Z、`…4gxBP1zWTy` 11-06 10:53Z 两次。
- **代价。**
  - 总调度 3 小时里 22 次用 Python 脚本往 dispatch.md 追加 CRLF 行、改 state.md；
  - W/Q 线 23 次文本编辑走 `run`；
  - Q13 追加时自己 LF→CRLF 转换了 8 次。
- 这一处 pi 的做法更好：pi 的 edit 先统一成 LF 做匹配，再把改动逐行拼回原文，没动的行保留各自的换行（`edit-diff.js`，11-17 讨论时读过）。

### 6. 守卫

- **拒绝 32 次**：`run` 19、`fs_op` 12、`job_start` 1。
- **确认的误伤 3 次：**
  - `Select-String -Pattern '…(stop|terminate|close|rm)'`：匹配到「`| rm`」；
  - `-Pattern '…|mkdir|rmtree'`：匹配到 `rmtree`；
  - Python 里 `batch, fi, ri = [], 0, 0`：`ri` 被当成 Remove-Item 的别名（`…cpKi9y6p9s` 17:17Z）。
  - AI 都只好把代码挪进文件再跑。
- **另有一次删已确认为空的目录**（`[IO.Directory]::Delete`，不递归）也被拒。
- 12 次是 11-15 想清理暂存目录里旧票的文件夹（`fs_op delete recursive`），照规矩拒绝，没错。
- 其余十几次的触发点在日志截断的 500 字以后，看不到；调用日志只记了「refused by a guard rule」，没记是哪条规则。

- **看时间**：`Get-Date` 出现在 1,988 个脚本里，199 次整条命令只为看时间。规矩要求记「电脑 Get-Date」时刻。

- **假的「卡住」**：Colab 驱动作业天生安静，被报「no output for 1241 s… take a screenshot」。
- **超时没说出来**：一个 6 小时的 lane 作业被自己的 `timeout_s` 结束，列表里 `reason` 是空的。
- **查内存、查进程**：AI 用 `Get-CimInstance` 查可用内存定 Codex 名额（6 次），查进程命令行；`proc_list` 和 `sys_info` 都给不了。
- **PowerShell 的坑反复踩**：变量名不分大小写（`$f` 覆盖了 `$F`）、函数名撞上内置别名、bash 式重定向。
- **排队程序读文件冲突**：排队程序改名 `queue.json` 时报 EPERM，崩过一次，一个在跑的作业被记成丢失（`…Wf51MRxYgt` 16:04Z）。派单里还专门提醒「读 queue.json 会让排队程序改名时报 EPERM」。

  - 这次是谁读着，没查清。

## 六、分轮建议

**第 1 轮：0.10.3 小修（约 1 天）**

1. **换行**：
   - `fs_write(append)` 跟随文件原来的换行；
   - `fs_edit` 统一成 LF 匹配，再逐行拼回原文的换行；
   - 只差换行时，提示直接这样说。
2. **`run-N` 的结果按时间保留**（至少 1 小时，不只最近 20 条）；有人在等它时绝不丢。
3. **`job_status()` 不带 id**：
   - 只列在跑的和最近结束的，每个一行状态，不带输出；
   - 加 `prefix=` 过滤；
   - 不带 id 时 `files=` 照样生效；
   - `job_stop` 只回摘要。
4. **`job_start(stdin_file=)`**：用电脑上的一个文件当 stdin。
5. **回复带电脑本地时间**：`run`、`job_status` 的结果里加一个 `now`。
6. **认更多写法**：`ui` 认 `tree`、`read`，当作 `inspect`；`window(action='read')` 按 `list` 办。找不到窗口时只列程序名，不列标签页标题。
7. **`ALWAYS_LOAD` 按用量**：去掉 `remote_run`，加上 `job_stop`、`history`。
8. **守卫拒绝时记出处**：调用日志里写明是哪个文件的第几条规则、原因是什么。

**第 2 轮：0.11.0 任务结束叫醒会话（先做 1 小时实测，再 2–3 天）**

1. **实测**：
   - 在云端会话，也在一个派生的子会话里，用后台命令把 POST `/hook/wait` 挂 50 秒；
   - 看沙箱代理放不放行、后台命令结束时会话醒没醒、从条件满足到会话醒来隔多久；
   - 顺带看子会话开场加载了哪些工具。
2. **`/hook/wait`（中转转给电脑）**，能等这几种条件，每次最多挂 50 秒：
   - 任务结束（按 id 或名字前缀）；
   - 任务输出或某个文件里出现某段文字；
   - 某个文件出现或变化；
   - 电脑上线（中转自己就能答）。
3. **叫醒命令直接给出**：`run` 的 `still_running`、`job_start`、`job_status` 的结果里，带一行可以直接放进后台运行的叫醒命令。开场说明、`help()` 改成「等任务就后台跑这一行，别定时回访」。
4. **一周后量**：每个任务问几次 `job_status`、从结束到被叫醒的延迟、`send_later` 和看门狗的次数、子会话的花费。

**第 3 轮：0.11.1 规矩瘦身（1–2 天）**

1. **`since` 改成按文件**：没变的文件只给路径和指纹；只在末尾追加了内容的文件，只给新增的那几行。
2. **超长的规则文件**：给标题目录加最新的部分，不再只给开头；截掉了什么、去哪儿读，说清楚。
3. **一周后量**：每个子会话收到的规矩总字节数，目标降一半以上。

**第 4 轮：0.12.0 多会话与离线（2–3 天）**

1. **任务设 `keep=true`**（给排队程序这种常驻程序用）：电脑重启、唤醒或 winhand 起来时，没正常结束的就重新拉起，不再靠每 10 分钟的巡检。
2. **断线更早发现**：比客户端的 60 秒更早发现连接已经死了，正在执行的调用尽快续上或给出明确报错（对应 11-12 那次）。
3. **任务状态更准**：
   - 「卡住」判断可以按任务放宽（`quiet_ok_s`）；
   - 被 `timeout_s` 结束的在列表里写明原因；
   - `run` 里的程序没起来时不报 0。
4. **`sys_info` 给负载**（可用内存、CPU），`proc_list` 能按命令行筛。
5. **读文件时允许别人改名或替换**（FILE_SHARE_DELETE），不再挡排队程序这类「写临时文件再改名」的保存。

**第 5 轮：0.12.1 守卫与安全（1–2 天）**

1. **守卫只看命令位置上的词**：引号里的搜索模式、Python 的变量名不算；删一个空目录不算批量删除。
2. **内置保护常见的登录信息**：浏览器配置、gcloud/Colab 的登录、`.netrc` 等，读和打包都拒。
3. **按第七节定的**：密码管理器窗口的截图和点击；暂存目录的清理（不跟联接点，带 keep 标记的不动）。

**以后再看**

- **第二台常开的电脑，或多机**：电脑是单道排队，又天天离线几小时，这是这期最大的物理限制。winhand 现在一个中转只认一台电脑。等你决定要不要加机器再说。
- **GitHub 信箱**：第 2 轮做通以后，巡检通知改走叫醒命令，旧总调度就不用再留着转发。
- **MCP tasks 进云端会话、连接器放开 60 秒**：出现了再说，并且先实测。
- **交互会话**（`session_*`，13 天 10 次）：这期的活用不上，不投入，但也不删。
- **pi 适配**：要是有人用 pi 当主机，写一个 pi 扩展，经 pi 的 Operations 接口把工具的 I/O 转给 winhand（见第五节）；winhand 自己的工具接口不改。
